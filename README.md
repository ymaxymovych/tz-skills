# TZ Skills — крос-перевірка технічних завдань для Claude Code

> **EN (short):** A [Claude Code](https://docs.claude.com/en/docs/claude-code) skill pipeline from a spoken idea to a verified implementation: `/tz-draft` structures your free-flow dictation (or rough draft) into a spec, asking only the few business questions it can't answer itself — all in ONE batched message (token economy), each with a recommended answer; skipped answers auto-take the recommendation (type «ФІНІШ» to accept them all and finish anytime); `/tz-review` audits the spec with **three independent LLMs of different vendors** against a 12-category checklist that starts with Job-to-be-Done & success criteria; `/tz-verify` checks it was truly implemented. **`/tz-go`** chains it ALL: it asks you exactly ONE question at the start — answer the spec questions yourself, or let it answer them all (silence = it answers) — then never blocks again. Either way it prints EVERY question with its recommended answer into the chat as soon as the list is ready, long before the code, so you can read and overrule while it keeps working; then it runs the review and implements the final spec to completion. Worktree isolation for the implementing agent is embedded in every generated spec. Each critic slot is pluggable: local **Claude / Codex / Gemini CLI**, **OpenRouter**, or **free NVIDIA NIM** models. Start with [docs/SETUP.md](docs/SETUP.md).

Конвеєр скілів для Claude Code, який прибирає головну проблему AI-розробки:
**Claude каже «зробив», а насправді відхилився від задачі або пропустив половину.**

```
надиктовка / чернетка ТЗ → /tz-draft → /tz-review → реалізація → /tz-verify
                          (структурує)  (аудит ТЗ)  (в ізольованому  (перевірка
                                                     worktree — це    виконання)
                                                     вшито у ТЗ)

надиктовка → /tz-go ─────────────────────────────────────────────→ готовий PR
             (той самий конвеєр ОДНИМ викликом: сам відповідає на власні
              питання, сам проганяє рев'ю, сам реалізує до кінця — тебе
              ніщо не чекає; свої рішення позначає в ТЗ для перечитування)
```

- **`/rozbir`** — студент запускає на етапі 1 курсу, **перед ТЗ**: останній реальний
  випадок і матеріали → одне Deep Research у своєму Chrome (Gemini або Perplexity) →
  три підходи й рекомендація → паспорт задачі та одна HTML-читанка. Код не пише.
  Паспорт підхоплюють `/tz-draft` і `/tz-go`; з `stop_after: spec` `/tz-go` завершує
  роботу на перевіреному ТЗ, перед дизайном та програмуванням.

- **`/tz-draft`** — **виговорюєшся 10-15 хвилин у вільному потоці** (або приносиш чернетку
  ТЗ) — скіл слухає не перебиваючи, впорядковує сказане, каже, як він зрозумів
  **Job-to-be-Done**, і питає **лише те, на що сам не може відповісти з високою
  впевненістю** (типово 0-3 питання, максимум 7). Усі питання приходять **ОДНИМ
  повідомленням-батчем** — це свідома економія токенів: кожен окремий раунд
  «питання-відповідь» змушує модель перечитувати всю історію чату. Кожне питання в
  батчі — **уже з рекомендованою відповіддю і поясненням, чому вона найправильніша**;
  відповідаєш одним повідомленням («1а, 2 так, 3 своя відповідь…»), а **пропущені
  питання автоматично беруть рекомендацію** (позначка ✅ у ТЗ). **Тільки
  бізнес-питання**; технічне (ОС, сервер, база, фреймворк) агент вирішує сам і записує у
  ТЗ секцією «рішення за замовчуванням». У кінці кожного повідомлення — кодове слово
  **«ФІНІШ»**: пишеш його — скіл приймає власні рекомендації на все, що лишилось, і
  одразу видає **підсилену версію ТВОГО ТЗ** (твої формулювання зберігаються, зміни
  перелічені у changelog вгорі) + команду для `/tz-review`. Кожне згенероване ТЗ містить
  вшиту інструкцію виконавцю: працювати в ізольованому git worktree і здавати через PR —
  студенту в git розбиратися не треба. Концепція — авторська; механіка питань адаптована
  з [Superpowers brainstorming](https://github.com/obra/superpowers) (MIT).

- **`/tz-review`** — перевіряє **технічне завдання (ТЗ) ПЕРЕД** тим, як віддати його в роботу.
  Три незалежні LLM читають ТЗ за фіксованим чек-листом з 12 категорій, **починаючи з
  категорії 0 — Job-to-be-Done і вимірювані критерії успіху** (далі безпека, дані,
  приховані припущення, крайні випадки, UX/UI…), 3 ітерації, з перевіркою фактів у вебі.
  ТЗ без чіткого JTBD і критеріїв успіху не проходить рев'ю по суті деталей — критики
  зобов'язані сказати це прямо. Результат — знайдені діри у ТЗ і покращена версія.

- **`/tz-go`** — **весь конвеєр одним викликом.** Ставить рівно ОДНЕ питання на старті:
  відповідати на питання ТЗ сам чи це зробиш ти (мовчання = відповідає сам) — і більше
  не зупиняється ніде. У будь-якому режимі **всі питання з рекомендованими відповідями
  виводяться в чат одним блоком одразу**, щойно список готовий: задовго до коду, щоб ти
  читав і міг перекреслити рішення, поки він працює далі. Для режиму
  «я виговорився — далі все сам, я потім перечитаю»: ізолюється у worktree, читає правила
  і пам'ять проєкту, будує ТЗ (що ПОЧИНАЄТЬСЯ з JTBD + критеріїв успіху + явних
  не-цілей «чого точно НЕ робимо»), інтерв'ює **сам себе батчами по 5 питань** із
  самокваліфікацією між батчами — сам вирішує, коли знає досить, щоб прийняти всі
  рішення (стеля 15; вердикт «чому зупинився» записується в ТЗ, кожна відповідь — з
  позначкою «✅ авто-прийнято (tz-go)», щоб людина могла перекреслити її однією
  правкою), проганяє повний `/tz-review`, перед першим рядком коду **фальсифікує
  головну гіпотезу ТЗ найдешевшим ручним тестом на живих даних** (A0: критики
  читають ТЗ, а не дані — ваду дизайну ловить лише живий прогін), а тоді реалізує
  фінальне ТЗ фаза за фазою до останнього критерію приймання — не зупиняючись і
  нічого не перепитуючи. Ставка явна: ~80% само-відповідей
  правильні, і неідеальна робота ЗАРАЗ цінніша за ідеальну, що чекає на людину. Єдине,
  що виноситься людині, — жорсткі зовнішні блокери (гроші, чужі акаунти, перша
  комунікація з реальною людиною) — і вони не зупиняють решту роботи, а стають чергою
  готових до виконання дій у фінальному звіті.

- **`/tz-verify`** — перевіряє, що **ТЗ реально виконано ПІСЛЯ** роботи, перед мерджем/деплоєм.
  Розбиває ТЗ на критерії приймання, і три незалежні LLM звіряють кожен критерій із реальним
  git-diff. Результат — вердикт з 5 рівнів
  (`BLOCK` / `FIX-FIRST` / `SAFE-TO-COMMIT` / `SAFE-TO-DEPLOY-AFTER-CHECK` / `INSUFFICIENT-EVIDENCE`)
  і чесний список: що зроблено, а що ні.

> **Про git-ізоляцію:** окремих worktree-скілів немає свідомо — студент не має розбиратися
> в git. Замість цього кожне ТЗ, згенероване `/tz-draft`, містить обов'язкову інструкцію
> агенту-виконавцю: створити ізольований worktree до першої правки, здати через PR після
> зелених перевірок, прибрати worktree після мерджу, а знищити незамерджену роботу — лише
> за явним словом «discard». Агент читає ТЗ і робить це сам.

## Чому це працює

Одна модель, яка сама пише і сама себе перевіряє — це «машина самопохвали». Тому обидва скіли
використовують **три РІЗНІ моделі різних вендорів** як незалежних критиків, які не бачать
відповідей одне одного. Розбіжність між ними — і є сигнал «дивись сюди уважно». Плюс жорсткі
запобіжники: кожна знахідка мусить цитувати конкретне місце (інакше відкидається як
галюцинація), захист від prompt-injection, перевірка фактів.

## Універсальність провайдерів

Три критики — це **абстрактні слоти** `critic_a` / `critic_b` / `critic_c`. Кожен через
`providers.json` підключається до будь-чого:

| Бекенд | Що це | Вартість |
|---|---|---|
| `claude-cli` | локальний Claude Code CLI | твоя підписка |
| `codex-cli` | локальний OpenAI Codex CLI | твоя підписка |
| `gemini-cli` | локальний Google Gemini CLI | безкоштовно/підписка |
| `openrouter` | будь-яка модель через OpenRouter API | платно per-token |
| `nim` | безкоштовні моделі NVIDIA NIM (DeepSeek, Qwen…) | **безкоштовно** |

Маєш **лише Claude**? Достатньо: `claude-cli` + дві різні **безкоштовні** NVIDIA NIM моделі.
Єдине жорстке правило — **три слоти = різні вендори** (два однакових = ехо, а не перевірка).
Усе маршрутизує один скрипт [`lib/llm-critic.sh`](lib/llm-critic.sh).

## Одна команда для нових студентів (ставить УСЕ)

Для Claude Code (Claude Desktop, вкладка Code) найпростіше одне речення: «Прочитай https://raw.githubusercontent.com/ymaxymovych/tz-skills/master/SEED.md і постав мені СКІЛ 0 у цю теку проєкту.» Або вручну:

Відкрий Git Bash (на Windows) або термінал у теці свого проєкту і виконай:

```bash
[ -d ~/tz-skills/.git ] && git -C ~/tz-skills pull --ff-only || git clone https://github.com/ymaxymovych/tz-skills.git ~/tz-skills
bash ~/tz-skills/lib/bootstrap-student.sh
```

**English-speaking users:** run the same command with `KIT_LANG=en bash ~/tz-skills/lib/bootstrap-student.sh` — installs 10 skills including `/rozbir` for stage 1 before writing a spec. The installer, its summary table and the IMMUNE rules block are then in English, and all four `/tz-*` skills answer in whatever language you write in.

`bootstrap-student.sh` ставить одним заходом: комплект «пам'ять проєкту»
[parallel-ai-dev](https://github.com/ymaxymovych/parallel-ai-dev) (клон + `init-memory` у проєкті),
10 скілів (зокрема `/rozbir` і чотири команди `/tz-*`), профіль критиків «лише Claude + 2 безкоштовні NIM», блок правил
IMMUNE у `CLAUDE.md` — і друкує чесну таблицю: що зелене, що лишилось людині (ключ NVIDIA)
чи Claude (заповнити декларації пам'яті). Нічого твого не перезаписує; повторний запуск безпечний.
Код виходу 1 = є червоні рядки зі списком «що зробити», а не поломка.

## Швидке встановлення (по кроках, якщо хочеш розуміти, що відбувається)

```bash
# 1. Клонувати
git clone https://github.com/ymaxymovych/tz-skills.git ~/tz-skills
cd ~/tz-skills
chmod +x lib/llm-critic.sh lib/tz-skills-update.sh skills/tz-verify/fanout-dispatch.sh

# 2. Поставити скіли у Claude Code (ця ж команда потім і оновлює)
bash lib/tz-skills-update.sh

# 3. Налаштувати провайдерів
cp providers.example.json ~/.claude/tz-providers.json
#   → відредагуй, обери профіль, встав ключі в ENV (див. docs/GET_FREE_TOKENS.md)

# 4. Перевірити
bash lib/llm-critic.sh --smoke-all      # усі три слоти → OK

# 5. Користуватись у Claude Code:
#    /tz-go                      (виговорись — одне питання на старті, далі ВЕСЬ конвеєр сам)
#    /tz-draft                   (виговорись 10-15 хв АБО дай чернетку — отримаєш повне ТЗ)
#    /tz-review шлях/до/ТЗ.md    (перед роботою)
#    /tz-verify шлях/до/ТЗ.md    (після роботи)
```

## Оновлення

```bash
bash ~/tz-skills/lib/tz-skills-update.sh          # стягнути свіже + перевстановити
bash ~/tz-skills/lib/tz-skills-update.sh --check  # тільки перевірити
```

Перевірка свідомо звіряє **дві** ланки — `GitHub → клон` і `клон → інсталяція`. Перевірка,
що дивиться лише на другу, зелена назавжди: старий клон вічно «відповідає» старій
інсталяції. Якщо до GitHub достукатись не вдалося, `--check` каже про це і повертає
помилку — мовчазного «все свіже» не буває. Деталі — [docs/SETUP.md](docs/SETUP.md#як-оновлюватись).

## Прикладні скіли поруч із конвеєром ТЗ

- **`/business-go`** (`skills/business-go/`) — від сирої ідеї до інвест-пакета за один прогін:
  самоінтерв'ю 10×3 → паспорт → deep research → кастдев → модель → GTM → дек/one-pager/MVP →
  критики. Оригінальні 8 промптів уроку — у `prompts.md` поруч.
- **`/lead-enrichment`** (`skills/lead-enrichment/`) — розгорнути у своїй CRM конвеєр веб-досьє
  на лідів перед дзвінком: SQL-черга → Gemini API з Google-пошуком (+ опційно браузерні
  Perplexity/ChatGPT) → власні перевірки в реєстрах → синтез у досьє → усе, включно з ПОВНИМИ
  сирими відповідями кожного двигуна, у власну базу. Схема досьє адаптується під бізнес через
  інтерв'ю (`INTERVIEW.md`). Несе `ARCHITECTURE.md` (контракти, ціна, покращення),
  `PITFALLS.md` (52 граблі з місяця щогодинних прогонів), `prompts.md`,
  `scripts/gemini-grounded.sh`.
- **`/hiring-kit`** (`skills/hiring-kit/`) — розгорнути у своєму проєкті модуль найму на
  20/80: анкета кандидата в Telegram-боті за deep-link вакансії → доказовий скоринг за
  скоркартою (гейти, 4 блоки, пороги 65/50) → канбан воронки зі стадіями, вердиктами,
  причинами й історією кожного контакту → повідомлення по стадіях → пул повторного контакту
  лише за згодою, по одному → імпорт наявної бази з дедупом. Ролі, гейти й бали
  адаптуються під бізнес через інтерв'ю (`INTERVIEW.md`). Несе `ARCHITECTURE.md`
  (сутності, стан-машина, контракт анкети, Prisma-референс), `PITFALLS.md` (45 граблів),
  `prompts.md` (три бойові анкети, каркас нової ролі, промпт LLM-скорингу з цитатами,
  шаблони повідомлень, 6 блоків співбесіди).
- **`/second-brain`** (`skills/second-brain/`) — розгорнути у своєму проєкті «другий мозок»:
  теми й питання власника задаються один раз → щотижня скрипт за розкладом шукає новини по
  кожній темі через headless Claude Code (веб-пошук + RSS, без платних API) → сам перевіряє
  URL, дати й повтори → дайджест тижня, живі сторінки тем, карта бази → коротко в Telegram
  (userbot або бот) → відповіді на «що я знаю про X» лише з бази з посиланням на файл і
  першоджерело → експорт однією HTML-сторінкою для колег. Розгортається одним реченням
  («Прочитай `~/tz-skills/skills/second-brain/SKILL.md` і розгорни в мене другий мозок»).
  Несе `ARCHITECTURE.md` (теки L0→L1→L2, контракти, розклад Windows/macOS, доставка,
  експорт), `PITFALLS.md` (26 граблів), `prompts.md` (ресьорч теми, оновлення сторінки,
  відповідь із джерелами, експорт), `scripts/brain.py` (один файл, лише stdlib Python).
- **`/second-brain`** (`skills/second-brain/`) — розгорнути особисту бібліотеку знань, що росте
  сама: назвати 3–7 тем → щотижня 5–10 перевірених знахідок на тему з URL і датою → дайджести,
  сторінки тем, `INDEX.md` → відповідь на «що я знаю про X» з посиланнями; експорт HTML для
  колег, доставка в Telegram. Несе `INTERVIEW.md`, `ARCHITECTURE.md`, `PITFALLS.md`,
  `prompts.md`, `scripts/brain.py`. Пам'ять власних розмов (транскрипти → нічні вижимки →
  `/recall`) — окремий сід: https://github.com/ymaxymovych/second-brain-seed.

## Стиснення довгих сесій: `/compact-prep` + мод `context-band`

Коли контекстне вікно заповнюється, Claude Code стискає розмову в резюме — і першими губить **причини
рішень**, відкинуті варіанти, точні значення і дослівні слова користувача. `/compact-prep`
(`skills/compact-prep/`) спершу зберігає довговічне у файли проєкту, а потім стискає розмову з
7-розділовим блоком (РІШЕННЯ, ЧЕРГА, ЗАРАЗ, ШЛЯХИ І ЗНАЧЕННЯ, ЛІЧИЛЬНИКИ, ВІДКРИТЕ, ІНСТРУМЕНТИ).

- **Мод `context-band`** (`mods/context-band/`, функціональні хуки Claude Code): смужка над полем вводу
  «Контекст N% · модель · effort» з кнопкою /compact-prep (підсвічується від 70 %); інструмент
  `compact_now` — скіл передає блок, і мод **сам** стискає сесію після відповіді (без ручної вставки);
  кожному стисненню — 7 розділів; після резюме код дописує ЧЕКПОІНТ: шлях до транскрипту, останні слова
  користувача дослівно, змінені файли, `git status`.
- **Хук PreCompact** — ті самі 7 розділів для автоматичного стиснення, працює і без мода.
- **Встановлення** — одним реченням Claude: «Прочитай `~/tz-skills/skills/compact-prep/SKILL.md`, розділ
  «Встановлення», і встанови compact-prep у мене» (або `bootstrap-student.sh` ставить усе сам).
  `scripts/install.py` безпечний для повторного запуску: робить копію `settings.json`, дописує лише своє.
- **Якщо мод не підтримується вашою версією Claude Code** — смужки не буде, а скіл працює запасним шляхом:
  друкує блок `/compact …`, який треба один раз вставити наступним повідомленням.

Виміряно на 1 109 реальних стисненнях: з блоком структура резюме вижила в 128/133 випадків, без нього —
0/860; живий прогін мода: 75,5 тис. → 15,8 тис. токенів без вставки, після стиснення 3/3 контрольні факти.

## Запобіжники агентів: `/agent-guards`

Хуки Claude Code, які самі виправляють або відхиляють команди, на яких агенти щотижня гублять години: `$` і лапки
в `git commit`, JSON у `curl`, кирилиця в cp866/cp1251, шляхи Git Bash на Windows, `.env` як код, промпт, з'їдений
прапором `claude -p`. Плюс розмикач петель (3-тя однакова відмова → підказка, 6-та → відмова повтору) і `measure.py`
для заміру «до/після». Замір автора 01–08.11.2026: ≈115 збоїв лапок і кодування за 8 днів і ≈1 100 механічних збоїв
агентів за тиждень; ефект запобіжників ще міряємо. Встановлення — `bash skills/agent-guards/install.sh`
(ідемпотентно; `bootstrap-student.sh` робить це сам); вимкнути — `AGENT_GUARDS_OFF=1`. Деталі:
[`skills/agent-guards/`](skills/agent-guards/README.md). Не перевірено на macOS.

## Поруч: коли чатів стає багато

Ці скіли тримають якість **однієї задачі в одному чаті**. Коли чатів стає кілька і вони
починають затирати роботу одне одного й забувати вже прийняті рішення — це вже інша
задача, і на неї є окремий репозиторій:
[**parallel-ai-dev**](https://github.com/ymaxymovych/parallel-ai-dev) — ролі
координатор/воркер, ізоляція у git worktree, зовнішня пам'ять у git (рішення, граблі,
карта проєкту) і запобіжник проти повторної побудови того самого.
