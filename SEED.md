# SEED: СКІЛ 0 — фундамент проєкту одним реченням

> Файл для Claude Code (Claude Desktop, вкладка Code). Студент вставляє одне речення:
> «Прочитай https://raw.githubusercontent.com/ymaxymovych/tz-skills/master/SEED.md і постав мені СКІЛ 0 у цю теку проєкту.»
> Далі все робиш ти. Повторний запуск безпечний.
> Необов'язково ДО цього: сід «Старт без ручних кліків» https://github.com/ymaxymovych/student-setup-seed — він налаштовує сам комп'ютер.

## Правила для Claude

- Студент — не програміст. Команд йому не показуй і не проси запускати; команди нижче — для тебе.
- Одна дія за раз; чекай слова «готово».
- Мова розмови й звітів — мова студента.
- Ключі в чат не друкуй. Нічого не видаляй з диска.
- Працюй у Claude Desktop → вкладка Code, у теці проєкту (може бути порожня). Якщо студент теку не обрав — запропонуй `~/Projects/<назва>`. Git Bash чи термінал студенту відкривати НЕ треба.
- Windows: скрипт — bash, запускай через Git for Windows. Якщо `bash` відсутній — постав сам: `winget install --id Git.Git -e --silent --accept-package-agreements --accept-source-agreements`, далі виклич `"C:\Program Files\Git\bin\bash.exe"`.
- macOS: якщо нема git, система покаже вікно встановлення інструментів розробника — студент тисне «Встановити».

## Крок 1. Інсталятор

З кореня теки проєкту:

```bash
[ -d ~/tz-skills/.git ] && git -C ~/tz-skills pull --ff-only || git clone https://github.com/ymaxymovych/tz-skills.git ~/tz-skills
bash ~/tz-skills/lib/bootstrap-student.sh
```

- Якщо тека ще не git-репозиторій — скрипт сам зробить `git init`.
- Якщо git не знає email — спитай ім'я й email студента ОДНИМ питанням і виконай `git config --global user.name …` та `user.email …`.
- Підсумкову таблицю покажи ЯК Є. Код виходу 1 — не поломка, а чек-лист «що зробити».

## Крок 2. Ключ NVIDIA (одна дія студента)

Якщо є червоний рядок про `NVIDIA_API_KEY`:

1. Поясни одну дію: відкрити https://build.nvidia.com (вхід через Google, картка не потрібна) → https://build.nvidia.com/settings/api-keys → Generate API Key → скопіювати ключ `nvapi-…`.
2. Ключ НЕ в чат. Додай у `~/.bashrc` рядок `export NVIDIA_API_KEY="ВСТАВТЕ_СЮДИ"` і відкрий цей файл у Блокноті (Windows) / TextEdit (macOS). Студент замінює текст у лапках на ключ і зберігає; скаже «готово».
3. Якщо студент усе ж вставив ключ у чат — один раз скажи «так більше не надсилайте», запиши його у файл сам і працюй далі.
4. Перевір: `source ~/.bashrc && bash ~/tz-skills/lib/llm-critic.sh --smoke-all` — усі три слоти мають відповісти OK.

## Крок 3. Інтерв'ю й заповнення пам'яті

Спитай ОДНИМ повідомленням, до кожного питання вказуючи рекомендовану відповідь (мовчання = рекомендація):

- репозиторій приватний чи публічний (у публічному робоча пам'ять публікується назавжди; рекомендація — приватний);
- один чат чи кілька паралельно;
- назва проєкту;
- де гроші, доступи, персональні дані (ризикові зони);
- команда перевірки й команда деплою, якщо є.

Що видно з коду (мова, тести, збірка) — визнач сам. Заповни: `coordination/SETUP.md`, секцію «Зони цього проєкту» в `CLAUDE.md`, `coordination/PROJECT_MAP.md` тим, що в проєкті ВЖЕ є, і `coordination/DECISIONS.md` — 3–5 рішень, видимих із коду, кожне з полем «Чому».

## Крок 4. Коміт і перевірка

Закоміть; запуш, якщо є remote. Повтори `bash ~/tz-skills/lib/bootstrap-student.sh` і покажи таблицю — має бути все зелене.
