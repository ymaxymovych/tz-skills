# /second-brain — обгортка над сідом second-brain-seed

**Джерело правди — `SEED.md` у репозиторії https://github.com/ymaxymovych/second-brain-seed
(СКІЛ 8 у групі «Мої скіли для студентів», крок на карті скілів).** Цей скіл його не копіює
і не змінює. Коли студент каже «/second-brain» або «розгорни другий мозок»:

1. Завантаж актуальний `SEED.md`:
   `curl -sL https://raw.githubusercontent.com/ymaxymovych/second-brain-seed/main/SEED.md -o SEED.md`
   (Windows PowerShell: `Invoke-WebRequest … -OutFile SEED.md`).
2. Прочитай його повністю і виконай усі фази до фінального звіту — так, як написано там.
3. Лише якщо студент — власник без програміста і хоче ТІЛЬКИ щотижневий ресьорч тем без
   пам'яті сесій Claude Code (§5 SEED), візьми додаток із цієї теки: `scripts/brain.py`,
   `INTERVIEW.md`, `PITFALLS.md`. Це реалізація §10 SEED «щотижневий ресьорч», не окрема система.

Нижче — той додаток (режим власника). Все, що суперечить SEED.md, програє SEED.md.

## Як розгорнути одним реченням

Студент пише в Claude Code у теці свого проєкту:

> Прочитай `~/tz-skills/skills/second-brain/SKILL.md` і розгорни в мене другий мозок

Далі Claude робить усе сам: проходить `INTERVIEW.md` (одне повідомлення з питаннями),
створює теки, копіює скрипт, ставить розклад, робить перший дайджест і перевіряє, що на
питання «що я знаю про <тема>» приходить відповідь із посиланням. Людина лише відповідає на
питання інтерв'ю і (якщо обрала Telegram без userbot) один раз створює бота в @BotFather.

**Звідки.** Запит власника виробничої компанії, жовтень 2026: «Перший крок із моделлю легкий —
спитати. Проблема, коли треба зробити другий: налаштувати ресьорч, де дані накопичуються,
структуруються, щоб була бібліотека. Щоб через 50 тижнів я міг сказати колезі: ось доступ у мій
другий мозок, там усе за рік — тренди, продукти, не втрачай час». Механіка — з нашої власної
пам'яті за методом Карпаті: сирі джерела → вижимки → правила, нічні прогони, пошук із цитатою.

## Language
Відповідай мовою користувача. «ФІНІШ» = «FINISH» = «DONE».

## Що ти будуєш (Job-to-be-Done)

Власник або керівник (не програміст) щотижня щось читає про ринок, але знання розсипане по
вкладках, чатах і голові. Через пів року він не може відповісти, що змінилось, і не може
передати це колезі. Йому треба: **один раз назвати теми**, далі **щотижня отримувати 5–10
перевірених знахідок на тему**, які **самі складаються в бібліотеку**, і **питати бібліотеку
словами** — з відповіддю, де кожен факт має джерело.

Критерії успіху (перевіряються):
1. За годину від старту розгортання існують `brain/TOPICS.md`, перший дайджест
   `brain/digests/<рік>-<тиждень>.md`, сторінки всіх тем і `brain/INDEX.md`.
2. Кожна знахідка в дайджесті має URL, дату публікації в межах вікна, «що нового» і «чому
   важливо мені». Знахідка без URL або дати до бази не потрапляє (відсікає скрипт, не модель).
3. Жоден URL не з'являється в дайджестах двічі (журнал `brain/sources/urls.tsv`).
4. Розклад стоїть і перевірений ручним запуском задачі планувальника; у `brain/logs/weekly.log`
   є рядок цього запуску.
5. Запит «що я знаю про <тема>» дає відповідь лише з `brain/` з посиланням на файл бази і URL.
6. `py -3 brain/brain.py check` (macOS/Linux: `python3 brain/brain.py check`) пише `OK`.

## Що входить (і тільки це)

| # | Капабіліті | Що закриває |
|---|---|---|
| 1 | **Теки бази** L0 → L1 → L2 + `INDEX.md` | одне місце для всього, зрозуміле людині й Claude |
| 2 | **`TOPICS.md`** — теми, питання, довірені джерела, RSS | налаштування один раз, правиться словами |
| 3 | **Щотижневий ресьорч** — `brain/brain.py weekly` за розкладом | бібліотека росте без участі людини |
| 4 | **Живі сторінки тем** — зведення + хронологія | «що ми знаємо зараз» замість 50 дайджестів |
| 5 | **Доставка в Telegram** (userbot СКІЛ 2 або бот) чи лише файл | знахідки доходять, а не лежать |
| 6 | **Відповіді з джерелами** — правило в `CLAUDE.md` | питаєш словами, отримуєш факт + URL |
| 7 | **Експорт для колег** — `brain-export/brain.html` | «ось доступ у мій мозок» без сервера |

**Шари за Карпаті, коротко.** L0 — сирі матеріали (`sources/`: відповіді пошуку як є, твої
PDF, статті, транскрипти). L1 — вижимки (`digests/`: що знайдено за тиждень, кожна знахідка з
URL). L2 — знання (`topics/`: що з усього цього випливає зараз, з посиланнями вниз). Питання
йдуть зверху вниз: L2 відповідає, L1 і L0 доводять. Сирі матеріали ніколи не видаляються —
саме вони дають перевірити, що модель нічого не вигадала.

## Що НЕ входить — і чому

- **Платні API пошуку (Perplexity API, SerpAPI, Exa)** — пошук робить headless Claude Code
  студента (`claude -p` з WebSearch), це вже оплачена підписка. Глибоке разове питання —
  Perplexity у браузері руками, результат кладеться в `sources/notes/`.
- **Векторна база і ембеддинги** — на кількох сотнях markdown-файлів Grep + `INDEX.md` знаходять
  швидше і прозоріше. Вектор має сенс від тисяч документів.
- **Власний сервер, вебсайт, логіни для колег** — експорт одним HTML-файлом і спільна тека.
- **Автоматичний парсинг платних видань і соцмереж за логіном** — обхід paywall і ToS.
- **Ресьорч щодня** — новин на тему за день мало, шуму багато; тиждень — природний ритм рішень.

## Порядок роботи скіла

0. **Прочитай файли поруч ПЕРЕД дією:** `ARCHITECTURE.md` (теки, формат `TOPICS.md`, потік
   тижневого прогону, доставка, розклад, експорт), `PITFALLS.md` (усі граблі, обов'язково),
   `prompts.md` (промпти, які читає скрипт), `INTERVIEW.md`.
1. **Подивись на проєкт:** ОС (`$env:OS` / `uname`), чи є git, чи є `CLAUDE.md`, чи є
   userbot СКІЛ 2 (теки/файли з `telethon`, `*.session`), чи є Python 3.9+ (`py -3 --version` /
   `python3 --version`). Чого бракує — встанови сам (Python: `winget install Python.Python.3.12`
   / `brew install python`).
2. **Інтерв'ю — ОДНИМ повідомленням** за `INTERVIEW.md`. З відповідей напиши `brain/TOPICS.md`
   за форматом з `ARCHITECTURE.md` §2.
3. **Структура:** створи `brain/sources/notes/`, `brain/digests/`, `brain/topics/`,
   `brain/logs/`; скопіюй `scripts/brain.py` → `brain/brain.py` і `prompts.md` →
   `brain/prompts.md` (скрипт читає промпти звідти). Дай `brain/README.md` на 10 рядків людською
   мовою: що де лежить і як питати.
4. **Секрети й шляхи:** `brain/.env` (шаблон — `ARCHITECTURE.md` §5) з `CLAUDE_BIN` — повним
   шляхом до `claude` (`(Get-Command claude).Source` / `command -v claude`) — і налаштуваннями
   доставки. Якщо проєкт у git — додай `brain/.env`, `brain/*.session` і `brain/logs/` у
   `.gitignore` ДО першого коміту.
5. **Доставка:** userbot СКІЛ 2 є → обгортка `brain/tg_send.py` (`ARCHITECTURE.md` §5),
   `TG_SEND_CMD` у `.env`, перевір одним тестовим повідомленням у «Збережені». Немає → бот
   через @BotFather (людина створює бота і надсилає йому `/start`; токен і chat_id ти береш
   сам, `ARCHITECTURE.md` §5). Обрано «лише файл» → `Доставка: файл` у `TOPICS.md`.
6. **Перший дайджест вручну:** `py -3 brain/brain.py weekly --no-send` (macOS/Linux:
   `python3 brain/brain.py weekly --no-send`). Прочитай дайджест: є знахідки, URL відкриваються,
   «чому важливо» стосується питання власника. Порожньо або мимо — правиш питання/ключові
   слова в `TOPICS.md`, а не скрипт, і запускаєш ще раз (повторний прогін тижня дописує, а не
   перетирає). Потім один запуск із доставкою — переконайся, що повідомлення прийшло.
7. **Правило відповідей:** допиши в `CLAUDE.md` проєкту блок «Другий мозок» з `prompts.md` §4.
   Перевір: спитай себе «що я знаю про <перша тема>» і переконайся, що відповідь цитує
   `brain/topics/…` і URL.
8. **Розклад:** `ARCHITECTURE.md` §6 — Windows Task Scheduler або cron, день і час з
   інтерв'ю. Запусти задачу примусово один раз і перевір рядок у `brain/logs/weekly.log`.
9. **Експорт для колег:** `brain/brain.py export`, поклади файл туди, куди обрав власник
   (`ARCHITECTURE.md` §7). Запиши обраний спосіб у `TOPICS.md` → `Доступ колег:`.
10. **Приймання** — чеклист нижче, і коротко людині: що стоїть, коли прийде перший
    автоматичний дайджест, як питати мозок.

## Чеклист приймання (усе — за годину від старту)

- [ ] `brain/TOPICS.md` — 3–7 тем, у кожної питання власника; мова, доставка, день/час,
      доступ колег записані.
- [ ] `brain/digests/<рік>-<тиждень>.md` згенеровано, у кожної знахідки URL, дата, «що нового»,
      «чому важливо мені»; ⚠️-позначки (сайт не пустив робота) перевірено очима.
- [ ] `brain/topics/*.md` — сторінка на кожну тему; `brain/INDEX.md` перелічує всі теми.
- [ ] Тестове повідомлення в Telegram прийшло (або доставка = файл).
- [ ] Задача планувальника створена, примусовий запуск залишив рядок у `brain/logs/weekly.log`.
- [ ] «Що я знаю про <тема>» → відповідь із `brain/…` і URL; «що я знаю про <тема поза базою>»
      → «у мозку про це нічого».
- [ ] `brain/brain.py check` → `OK`.
- [ ] `brain-export/brain.html` відкривається, карта тем і теми на місці.
- [ ] `brain/.env` не в git (`git check-ignore brain/.env` друкує шлях).

## Рішення, які НЕ обговорюються (перевірено)

- URL і дату перевіряє **скрипт**, а не обіцянка моделі: без URL, без дати, дата поза вікном,
  404 — знахідка відкидається з рядком у лозі.
- Модель повертає JSON; markdown дайджесту збирає скрипт. Формат не «плаває» від тижня до тижня.
- Хронологію теми дописує скрипт; модель переписує лише зведення зверху.
- Ліміт знахідок на тему (за замовчуванням 7, стеля 10) — краще 3 сильні, ніж 10 слабких.
- Відповідь із бази — лише з `brain/`; чого немає — «у мозку про це нічого».
- Усі шляхи скрипт рахує від свого розташування — розклад працює з будь-якого робочого каталогу.
- Помилка теми не валить інші теми, але завершує прогін з ненульовим кодом і рядком у лозі —
  тихого «успіху» немає.

## Артефакти в проєкті

```
brain/
  TOPICS.md            теми, питання, джерела, RSS, налаштування (правиш ти)
  INDEX.md             карта тем, дайджестів, твоїх матеріалів (генерує скрипт)
  README.md            що де лежить, як питати
  brain.py · prompts.md
  .env                 шлях до claude, доставка (НЕ в git)
  sources/             L0: <тиждень>/<тема>.raw.md, <тема>.json, urls.tsv, notes/ (твої файли)
  digests/             L1: <рік>-<тиждень>.md
  topics/              L2: <тема>.md — «що знаємо зараз» + хронологія
  logs/weekly.log
brain-export/brain.html  для колег
```

Якщо проєкт у git — коміт після розгортання і (за бажанням) після кожного тижневого прогону:
історія бази тоді видна в git.
