# Архітектура другого мозку

Референс — наша власна пам'ять (сирі транскрипти → нічні вижимки → правила, пошук із цитатою).
Тут — найменша версія, що переноситься в будь-який проєкт: одна тека `brain/`, один скрипт
`scripts/brain.py` (лише стандартна бібліотека Python 3.9+), два промпти в `prompts.md`.
Нічого, крім Python і залогіненого Claude Code, ставити не треба.

## 1. Схема

```
brain/TOPICS.md (теми, питання, джерела, RSS, налаштування)
   │  планувальник: щотижня, день/час з інтерв'ю
   ▼
brain.py weekly ── для кожної теми ─────────────────────────────────────────────┐
   │ [A] RSS-стрічки теми → свіжі пункти за вікно (urllib + xml)                 │
   │ [B] claude -p --allowedTools WebSearch WebFetch  ← промпт prompts.md §2      │
   │       вхід: тема, питання, джерела, RSS, минулий дайджест, бачені URL        │
   │       вихід: JSON [{title, url, date, source, what, why}]                    │
   │       сирий вивід → sources/<тиждень>/<тема>.raw.md   (L0)                   │
   │ [C] фільтр скрипта: є URL · є дата · дата у вікні · URL не в urls.tsv ·      │
   │       сторінка відкривається (404 → геть; 403/429 → ⚠️ «перевір вручну»)       │
   │       · не більше ліміту                                                     │
   │ [D] sources/<тиждень>/<тема>.json (прийняте) · urls.tsv += URL               │
   │ [E] topics/<тема>.md: зведення ← claude -p (prompts.md §3, без інструментів) │
   │       + хронологія ← скрипт дописує тиждень зверху                (L2)       │
   └─────────────────────────────────────────────────────────────────────────────┘
   ▼
digests/<рік>-<тиждень>.md (L1) → INDEX.md → [експорт у спільну теку] → Telegram (коротко)
   ▼
logs/weekly.log; помилка будь-якої теми = ненульовий код виходу

Питання власника в Claude Code → правило «Другий мозок» у CLAUDE.md →
   INDEX.md → topics/ → digests/ → sources/ → відповідь з (файл; URL, дата)
```

## 2. `brain/TOPICS.md` — формат

Рядки `Ключ: значення` до першого `## ` — налаштування. Кожна `## Назва` — тема, під нею
поля `- Поле: значення`. Скрипт читає лише ці поля; решту тексту можна писати вільно.

```markdown
# Теми другого мозку

Мова: українська
Доставка: telegram
Знахідок на тему: 7
Вікно днів: 14
Розклад: понеділок 08:00
Доступ колег: Google Drive, тека «Другий мозок»
Експорт у: C:\Users\olena\Google Drive\Другий мозок

## Тренди білкової їжі
- Питання: що змінюється в попиті на білкові снеки й напої в ЄС і Україні
- Ключові слова: high-protein snacks, protein bars, білкові батончики, попит
- Джерела: foodnavigator.com, fooddive.com, mintel.com (запропоновано)
- RSS: https://www.foodnavigator.com/arc/outboundfeeds/rss/

## Регуляторика маркування
- Питання: які нові вимоги до етикеток харчових продуктів в ЄС і Україні набирають чинності
- Ключові слова: food labelling regulation, маркування харчових продуктів, Держпродспоживслужба
- Джерела: eur-lex.europa.eu, food.ec.europa.eu, dpss.gov.ua
```

| Поле | Обов'язкове | Що робить |
|---|---|---|
| `Мова` | ні (українська) | мова «що нового» / «чому важливо» і зведень |
| `Доставка` | ні (telegram) | `telegram` — шле підсумок; будь-що інше — лише файл |
| `Знахідок на тему` | ні (7) | ліміт на тему за прогін, стеля 10 у коді |
| `Вікно днів` | ні (14) | приймаються публікації не старші за N днів |
| `Експорт у` | ні | тека, куди після прогону копіюється `brain.html` |
| `Розклад`, `Доступ колег` | ні | для людини; розклад ставить планувальник (§6) |
| `- Питання` | так | головне, що відрізняє знахідку від шуму |
| `- Ключові слова`, `- Джерела` | ні | підказка пошуку; джерела — шукати там першими |
| `- RSS` | ні | адреси через пробіл або кому; лише ті, що реально відкриваються |

Вікно 14 днів при тижневому запуску — навмисне перекриття: публікація, яку пошукова система
проіндексувала із запізненням, не випадає; дублікати відсікає `urls.tsv`.

## 3. Тижневий прогін — контракти

**Знахідка** (від моделі, JSON): `title`, `url`, `date` (YYYY-MM-DD), `source`, `what` (2–3
речення з фактом), `why` (одне речення про питання власника). Модель повертає масив без
тексту навколо; скрипт бере перший `[...]` з відповіді.

**Фільтр скрипта** — порядок і причина відкидання пишуться в лог:
`без URL` → `без дати` → `дата поза вікном` (і майбутні дати) → `вже було` (нормалізований
URL у `urls.tsv` або повтор у цьому ж прогоні) → `не відкривається` (404/410, DNS, таймаут).
403/429/5xx не відкидаються: багато видань ріжуть роботів — знахідка йде з ⚠️.

**Нормалізація URL**: нижній регістр хоста, без `www.`, без `utm_*`/`fbclid`/`gclid`, без
кінцевого `/`, без `#…`.

**`sources/urls.tsv`**: `url<TAB>тиждень<TAB>тема` — журнал усього прийнятого. Це і дедуп, і
відповідь на «звідки в базі цей факт».

**Тиждень** — ISO-тиждень (`date.isocalendar()`): 29.12.2025 — це `2026-01`, не `2025-53`.

**Повторний прогін того ж тижня** дописує нові знахідки до `sources/<тиждень>/<тема>.json` і
перезбирає дайджест з усього файлу; у хронології теми знахідки додаються під той самий
заголовок тижня. Нічого не перетирається.

**Сторінка теми** `topics/<тема>.md`:

```
# <Тема>
> Питання: …
> Оновлено: 2026-41
## Що ми знаємо зараз      ← переписує модель (prompts.md §3), кожен пункт з (джерело, дата)
## Тренди
## Відкриті питання
## Хронологія              ← дописує лише скрипт: ### 2026-41 + знахідки, свіжі зверху
```

Тиждень без знахідок зведення не чіпає (модель не викликається).

**`INDEX.md`** генерується повністю щоразу: теми з кількістю знахідок, дайджести (свіжі
зверху), «Мої матеріали» з `sources/notes/`.

## 4. Виклик Claude Code

```
<CLAUDE_BIN> -p --output-format text --allowedTools WebSearch WebFetch   (промпт — у stdin)
```

- Промпт іде через stdin в UTF-8, не аргументом: аргумент на Windows ламає кирилицю і
  впирається в ліміт довжини командного рядка.
- `cwd` = корінь проєкту: headless Claude бачить `CLAUDE.md` проєкту.
- Таймаут 15 хв на тему. 5 тем — зазвичай 10–25 хв на весь прогін.
- Оновлення зведення — той самий виклик без `--allowedTools`: там пошук не потрібен і
  заборонений (модель має працювати лише з даними тижня).
- Квота: кожна тема — один сеанс пошуку. На підписці Pro 5–7 тем раз на тиждень проходять
  без проблем; якщо прогін збігся з вичерпаною квотою — тема падає з помилкою в лозі,
  наступного тижня вікно 14 днів підбере пропущене.

## 5. `brain/.env` і доставка

```
# приклад; значення Claude бере на місці при розгортанні
# шлях до Claude Code — планувальник не бачить PATH терміналу
CLAUDE_BIN=C:\Users\olena\.local\bin\claude.exe
# варіант А: userbot СКІЛ 2 — команда, що читає текст зі stdin і шле в Telegram
TG_SEND_CMD=py -3 brain/tg_send.py
# варіант Б: бот з @BotFather
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

Скрипт бере `TG_SEND_CMD`, якщо він є, інакше бот. `Доставка: telegram` без жодного з них —
помилка з ненульовим кодом (не тихий пропуск).

**Варіант А — `brain/tg_send.py` поверх userbot СКІЛ 2.** Подивись, як userbot у проєкті
створює клієнт (файл сесії, `api_id`, `api_hash` — зазвичай у його `.env`), і повтори це:

```python
import asyncio, sys
from pathlib import Path
from telethon import TelegramClient

# ті самі значення, що в userbot СКІЛ 2 — прочитай їх з його .env, не копіюй у код
API_ID, API_HASH = ..., ...
SESSION = str(Path(__file__).resolve().parent / "brain_sender")  # ОКРЕМА сесія, див. PITFALLS №12

async def main():
    text = sys.stdin.buffer.read().decode("utf-8")
    async with TelegramClient(SESSION, API_ID, API_HASH) as client:
        await client.send_message("me", text, link_preview=False)  # "me" = «Збережені»

asyncio.run(main())
```

Окрема сесія `brain_sender.session` створюється один раз інтерактивно (код із Telegram
приходить людині) — це єдиний крок, де людина вводить код; далі працює без неї. На macOS/Linux
`TG_SEND_CMD=python3 brain/tg_send.py`.

**Варіант Б — бот.** Людина: @BotFather → `/newbot` → надіслати своєму боту `/start`. Claude:
токен у `.env`; `chat_id` — з `https://api.telegram.org/bot<токен>/getUpdates` (поле
`message.chat.id`), відкрити цю адресу Claude робить сам скриптом, не просить людину.

Повідомлення: заголовок тижня, по кожній темі до 3 знахідок (заголовок + URL), шлях до
повного дайджесту. Нарізка по 4000 символів по межах абзаців.

## 6. Розклад

**Windows (PowerShell, з кореня проєкту)** — `Register-ScheduledTask`, а не `schtasks`: лише
так вмикається «запустити, щойно комп'ютер прокинувся».

```powershell
$pyw = (Get-Command pyw).Source
$root = (Get-Location).Path
$action = New-ScheduledTaskAction -Execute $pyw -Argument "-3 `"$root\brain\brain.py`" weekly" -WorkingDirectory $root
$trigger = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Monday -At 08:00
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Hours 2)
Register-ScheduledTask -TaskName "SecondBrainWeekly" -Action $action -Trigger $trigger -Settings $settings -Force
Start-ScheduledTask -TaskName "SecondBrainWeekly"
```

`pyw` — без вікна консолі (скрипт і так пише все в `brain/logs/weekly.log`). День і час —
з інтерв'ю (`-DaysOfWeek Sunday -At 20:00` тощо). Перевірка: через 1–2 хв
`Get-ScheduledTaskInfo SecondBrainWeekly` → `LastTaskResult` (0 = успіх; 267009 = ще працює),
і новий рядок у лозі.

**macOS / Linux (bash, з кореня проєкту)**:

```bash
ROOT="$(pwd)"
PY="$(command -v python3)"
( crontab -l 2>/dev/null | grep -v 'brain/brain.py weekly'
  echo "0 8 * * 1 cd \"$ROOT\" && \"$PY\" \"$ROOT/brain/brain.py\" weekly >> \"$ROOT/brain/logs/cron.log\" 2>&1"
) | crontab -
crontab -l | grep brain.py
```

Перевірка без чекання понеділка: та сама команда з crontab вручну, потім рядок у
`brain/logs/weekly.log`. `0 8 * * 1` = понеділок 08:00; неділя 20:00 = `0 20 * * 0`.

## 7. Експорт і доступ колег

`brain.py export` → `brain-export/brain.html`: одна сторінка без зовнішніх файлів — карта тем
нагорі, далі сторінки тем, далі дайджести (свіжі зверху), внутрішні посилання — якорі,
зовнішні — URL першоджерел. Світла/темна тема за системою, читається з телефону.

| Спосіб | Як | Коли |
|---|---|---|
| Спільна тека Google Drive / OneDrive | `Експорт у: <тека синхронізації>` у `TOPICS.md` — після кожного прогону файл копіюється туди сам; доступ «читач» колегам через інтерфейс Drive | клієнт Drive вже стоїть на комп'ютері |
| Приватний репозиторій GitHub | `brain/` у git, колеги з правом Read; GitHub сам показує markdown, а колега з Claude Code клонує і питає базу своїм Claude | колеги працюють у Claude Code |
| Файл у Telegram | `brain-export/brain.html` надіслати як документ | разово, «скинь, що є» |

Google Drive не показує HTML у браузері — колега завантажує файл і відкриває локально; markdown
`.md` Drive показує як текст. Свої PDF/нотатки з `sources/notes/` в експорт не входять —
лише назви.

## 8. Рішення за замовчуванням (не питати людину)

| Питання | Рішення | Чому |
|---|---|---|
| Мова скрипта | Python, лише stdlib | є на всіх ОС, нічого не ставити через pip |
| Пошук | `claude -p` + WebSearch/WebFetch | уже оплачено підпискою, бачить сторінки, а не лише сніпети |
| Формат бази | markdown + json + tsv | читається людиною, Grep, git-diff |
| Де промпти | `brain/prompts.md` | правка тексту без правки коду |
| Пошук по базі | Grep + `INDEX.md` | на сотнях файлів швидше і прозоріше за вектор |
| Розклад Windows | Task Scheduler, `pyw`, StartWhenAvailable | без вікна, не пропускає сплячі понеділки |
| Розклад macOS/Linux | cron | одна команда; launchd — лише якщо ноутбук регулярно спить у цей час |
| Назви файлів тем | слаг назви теми (кирилиця дозволена) | людина впізнає файл |
| Перейменування теми | перейменувати `## …` І файл `topics/<старий>.md` разом | інакше створиться нова порожня сторінка |
