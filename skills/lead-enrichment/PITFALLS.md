# Граблі конвеєра веб-досьє — усі, на які ми наступили (18.08 → 09.09.2026)

> Витяг із ~3 000 рядків плейбука щогодинного воркера. Формат: **що зламалось → чому →
> як робити далі.** Твій Claude має прочитати це ПОВНІСТЮ перед тим, як проєктувати свій
> конвеєр. Кожен пункт коштував нам щонайменше один зіпсований прогін.

## A. Дані і черга

1. **Досліджено ЧУЖОГО ліда через стейлий файл** (30.08, найдорожча помилка: 2/3 прогону в
   стіл). Ланцюг `curl -o /tmp/q.json && python3 …` — віндовий python не бачить `/tmp` git-bash,
   впав, а наступний `tail /tmp/prompt.txt` надрукував файл ВЧОРАШНЬОГО ліда. → Дані ліда
   бери лише з JSON відповіді черги в тому ж виклику; звіряй `name` з черги з іменем у тексті;
   тимчасові файли `rm -f` на старті прогону; між кроками `&&`, падіння одного — стоп.
2. **Лід крутиться в черзі вічно**, бо порожнє чесне досьє не імпортували. → Умова виходу з
   черги — «воркер торкався» (префікс моделі), а не «є джерела». Порожнє досьє імпортується.
3. **`NOT IN` на nullable-колонці мовчки викидає NULL** (стадія NULL = лід зникає з вибірки при
   449 зелених тестах — мок-сховище форму `where` не перевіряє). → колонка NOT NULL або
   `OR col IS NULL`; після деплою — живий SQL, не тести.
4. **У картку одного ліда записався профіль ІНШОЇ компанії цілком** (26.08): імпорт приймав
   будь-який текст для будь-якого leadId. → Сторож якорів: домен/назва/поштовий домен ліда
   мусить бути в тексті, інакше 422. Лід без якорів проходить (fail-open).
5. **Сторож якорів ріже власне чесне «сайту немає»**, якщо домен у тексті не згадано. →
   у порожньому досьє домен ЗГАДУЙ явно («сайт X не існує»).
6. **Поле `sources` легко забути, і воно мовчки губиться** (API ріже до 10, порожнє —
   приймає). → перевіряй `sourcesCount` у відповіді імпорту; 0 допустимо лише при чесному нулі.
7. **Не-відповідь двигуна записана як відповідь** (08.09: «ПРОПУЩЕНО…» лягло в базу як
   «відповідь Gemini»). → двигун не відповів = елемента немає; ніяких «пропущено» в text.
8. **Сирі відповіді гинули разом із сесією** — зберігали лише синтез. → окрема рядкова
   таблиця під повний текст кожного двигуна + журнал власних перевірок.
9. **Дублі однієї компанії в черзі** (4 ліди з одного домену). → дедуп по домену/коду
   юрособи ДО прогону: другий лід бере досьє з бази.
10. **Сміттєва заявка (лайка в ПІБ, телефон +380687777777, «telegram @nick» замість компанії)
    зʼїдає повний прогін.** → гейт «сміття» до черги; одразу junk-досьє з `confidence: low`,
    інакше запис повертається щогодини.

## B. Двигуни: браузер

11. **Вставка тексту: `type` частинами і `form_input` не працюють** у contenteditable
    (Perplexity — Lexical, ChatGPT — ProseMirror). → справжній клік у поле, потім JS-цикл
    `document.execCommand('insertText', false, chunk)` по 300 знаків в ОДНОМУ виклику; один
    довгий insertText повертає true і нічого не робить; переноси рядків прибрати (Enter =
    надіслати); `innerText` одразу після вставки віддає старе значення — перевіряй окремо.
12. **Enter/пробіл через `type` не надсилає** ні в Perplexity, ні в ChatGPT. → кнопка
    надсилання через `.click()` з JS (у Perplexity `aria-label="Submit"` англійською навіть в
    українському UI); доказ відправки — `location.href` змінився на `/c/…`, а не порожнє поле.
13. **Perplexity: редактор не чіпай узагалі** — чернетка переживає reload і ламає range-selection.
    → лише URL `https://www.perplexity.ai/search?q=<encodeURIComponent(промпт)>`.
14. **Perplexity ОБРИВАЄ довгий вивід ЗАВЖДИ** (3 з 3, обрив і на 998 знаках; «до 3 500 знаків»
    у промпті не рятує). → плануй, що Perplexity дає лише початок; факти — з ChatGPT і
    власних перевірок; у синтезі бери ОСТАННЄ входження JSON у `innerText` (перше — луна схеми).
15. **Perplexity видає ретельно оформлений ХИБНИЙ НУЛЬ** («ідентифікувати неможливо» з
    переліком «неперевірених» джерел) — двічі за два дні, коли власна перевірка закривала ліда
    за 40 с. → впевнений нуль двигуна перевіряй так само прискіпливо, як гучне «знайдено».
16. **ChatGPT у фоновій вкладці НЕ рендерить відповідь** (віртуалізація: у DOM лише видима
    частина, `get_page_text` віддає список джерел). → reload перед читанням; беріть
    МАКСИМУМ із трьох способів (`.markdown` найдовший / range-selection / скрол-збирання),
    не довіряйте одному; **розмір вікна 1100×760** — 1280×900 і 1500×2600 ламають витягування.
17. **ChatGPT вигадує НАЙСИЛЬНІШИЙ доказ ідентичності** (точний email/телефон «на сторінці»,
    яких там немає) — рахунок вигадок по прогонах 3:1, 2:3, 1:3. → факт, що вирішує
    ідентичність (email, телефон, код юрособи, посада), відкривай очима на самій сторінці.
18. **Зведення пошуку «поверх» результатів — не джерело** (WebSearch дописав «contact email
    listed as …», на сторінці адреси не було). → джерело — сторінка; сніпет — підказка.
19. **Gemini у ФОНОВІЙ вкладці не надсилає промпт — 8 прогонів поспіль** (кнопка знаходилась,
    клікалась, Enter/Ctrl+Enter — нічого). Діагноз: вкладка групи автоматизації завжди
    `visibilityState: hidden`, і сторінка Gemini лишається SSR-оболонкою без застосунку. →
    Gemini через API з `google_search` (детермінований, без браузера); у браузері — не пробувати.
20. **DLP-фільтр інструмента блокує РЕЗУЛЬТАТ виклику**, якщо в ньому URL з query або
    email (`[BLOCKED: Cookie/query string data]`), і чистити збережену змінну потім — пізно.
    → санітизуй у ТОМУ Ж виклику, до того, як рядок стане значенням: URL → `[url]`, `[?&=]…`
    вирізати, email → `[email]`; домени — третім правилом.
21. **Вкладки лишаються відкритими, ПК гальмує; групу вкладок «розвалило»** (5 вкладок у трьох
    Chrome, `navigate` без tabId теж створює вкладку). → журнал кожної відкритої вкладки у
    файл того ж ходу; один браузер на прогін; закривати у ЗВОРОТНОМУ порядку створення,
    вкладку-засновницю групи — ОСТАННЬОЮ; підсумок без «вкладки: закрито N/N» = прогін не
    виконано.
22. **Два Chrome підключені → інструмент вимагає «спитати користувача»**, якого у планової
    задачі немає. → `list_connected_browsers` → перший deviceId з Chrome → перевір логін
    через DOM; порожній список = Chrome не підключений → прогін пропущено, НЕ переходити в
    Playwright/Edge (05.09 воркер відкрив два чужі браузери без логінів і спалив 18 млн
    токенів без жодного двигуна).
23. **Класифікатор дозволів блокує стохастично** («Blocked by classifier» в auto-режимі). →
    просто повтори виклик; правила дозволів — у settings заздалегідь.
24. **Скріншоти в браузері = тисячі токенів кожен**, планові воркери робили їх десятками. →
    сторінка читається лише текстом/DOM; скріншоти заборонені хуком.

## C. Двигуни: API

25. **Perplexity API «працює, але набагато гірше за браузер»** (sonar-* не знайшли компанію,
    яку браузерний Pro Search знайшов із самих email+телефона) і ключ мовчки вичерпав квоту
    за 4 доби, валячи все на гіпотезу без вебу. → API не ставити першим; тихий фолбек на
    «без вебу» рахувати окремим лічильником і алертити.
26. **`gemini-2.5-flash` → 404 «no longer available to new users».** → `gemini-3.6-flash`;
    список моделей питай живим `GET /models`, не з памʼяті.
27. **`thinkingBudget: 0` → 400 на Gemini 3.x**, а без обмеження роздуми зʼїли 923 з 1 024
    токенів виводу — текст порожній при HTTP 200. → `thinkingConfig.thinkingLevel: "low"`,
    `maxOutputTokens` 8192; перевіряй `finishReason` і довжину тексту, не лише код відповіді.
28. **URL джерел від grounding — редіректи `vertexaisearch…/grounding-api-redirect/…`**, не
    сторінки. → HEAD без follow, бери `Location`; що не резолвиться — залишай із позначкою.
29. **Два з трьох ключів одного власника → 429 RESOURCE_EXHAUSTED** (акаунти без кредитів),
    `GET /models` при цьому 200 — «ключ живий» нічого не доводить. → живість = реальний
    generateContent; список ключів через кому з перебором на 429; алерт, коли всі вичерпані.
30. **Ключ із білінгом без ліміту витрат** — після кредитів списує з картки без попередження.
    → добова стеля викликів у коді + budget cap у консолі провайдера.
31. **Модель зникає з каталогу провайдера мовчки** (NIM зняв модель через 2 дні після вибору;
    LiteLLM-fallback підмінив мертву модель). → перевірка живості моделі = виклик, не
    каталог; сторож на «тиха підміна моделі».

## D. Синтез і якість

32. **Два двигуни розходяться саме там, де найдорожче** (один — confidence high за збігом ПІБ,
    другий — «звʼязку нема»). → обережніша версія перемагає; розбіжність у caveats.
33. **Лише збіг ПІБ — не ідентифікація.** → сила доказу: домен+телефон на сайті > ПІБ у реєстрі
    +домен+телефон у каталозі > збіг ПІБ (max medium, компанію в опенері не називати).
34. **Штат 90 людей ≠ 90 учнів; заявлений штат розходиться з офіційним у 5 разів** → це
    матеріал для розмови, а не тихе виправлення; sizeBand від заявленого, суперечити — лише
    з джерелом.
35. **Юрособа ≠ група** (17,8 млн дохід сервісної фірми проти ≥1,6 млрд по групі заводів —
    лід занижено на два порядки). → перевіряй ознаки групи; масштаб консолідовано; у досьє
    кажи, ПО ЯКИХ юрособах.
36. **КВЕД №1 не те, чим бізнес здається; розбіжність КВЕДів — не спростування.** → спершу
    «Про нас» на сайті.
37. **Збіг назви в реєстрі — пастка**, чіпляти код юрособи лише після звірки КВЕД/міста.
38. **Сніпет Google приліпив телефон до шести чужих Instagram-акаунтів різних міст** (склейка
    сусідніх результатів у стрічці однотипних рілсів). → відкривай ≥2 найправдоподібніші
    сторінки і греп сирий HTML; збіг зараховуй лише з профільного URL.
39. **Google в лапках матчить нечітко; Prozorro API — теж.** → відкривай і перевіряй буквально.
40. **Розробник застосунку в Google Play ≠ власник бізнесу; `/employer/my/` на work.ua — ТВІЙ
    акаунт, не роботодавець; профіль на біржі фрилансу = сигнал «НЕ власник бізнесу».**
41. **Двигун датував статтю 2017 року як подію 2025-го.** → дати перевіряй на сторінці.
42. **Найкраща цифра досьє — не абсолют, а пара**: «дохід +28 % при прибутку −23 %» або
    «виторг на працівника по роках» — це готовий аргумент, сильніший за опис болю.
43. **Клас ліда, якого не було в рамці: конкурент/колега з нашого ринку.** → `leadScore`
    рахувати двічі (як покупця / як партнера) і сказати це вголос; не підганяти під рамку.

53. **Два замки на один тік = крон, який ніколи не бігає при зелених тестах.** Обгортка крона
    вже брала системний замок `cron:<name>`; другий `withSystemLock` із тим самим ключем усередині
    обробника завжди повертав «зайнято», і роут відповідав `{"skipped":"locked"}` — успіхом.
    Спіймано лише живим dryRun на проді після деплою (тести роут не покривали). → перед тим, як
    додавати запобіжник, перевір, чи його вже не дає обгортка; після деплою будь-якого крона —
    один живий виклик із `dryRun` і прочитати відповідь очима.

## E. Витрата і механіка прогону

44. **Один лід коштував 110–240 викликів і 23–36 млн токенів** — непропорційно досьє для одного
    дзвінка. → стеля 25 хв / 80 викликів на лід; двигуни паралельно; результати сторінок у
    `window.__x`, читати зрізами; не переписувати великі тексти в чат.
45. **Порожній прогін коштував ~280K токенів** — плейбук на 1 800 рядків читався щогодини
    заради «черга порожня». → плейбук окремим файлом, читається лише коли є робота; порожня
    черга → одна фраза і кінець.
46. **Стеля в промпті — не механічний замок** (тримається на слухняності моделі). → лічильники
    в запускачі; те саме для «працює лише на цій машині» (інструкції синхронізуються між
    машинами, розклад — ні → дві машини оброблять чергу двічі).
47. **Bash-heredoc помирає на українських апострофах** (JSON із «Компанія "Лілея"…»). → payload
    писати через Write у файл, слати `--data @file`.
48. **`/tmp` у git-bash і у віндовому python — різні теки.** → абсолютний windows-шлях
    скретчпаду однаково в обох інструментах.
49. **Bing same-origin fetch вичерпується після ~10–12 запитів і віддає сміття; DDG html —
    капчу.** → Google у вкладці (~25 запитів без деградації); капчу обходити заборонено.
50. **SSH таймаутить після зміни домашнього IP** (Cloud Firewall по IP) і секрет приходить
    порожнім → GET віддає `Unauthorized`, що схоже на «черга порожня». → перевіряй код
    відповіді, не лише порожній `items`; резервний шлях до сервера (Tailscale).
51. **Планувальник показує «успіх» за запуск процесу, не за роботу** (два воркери мовчали
    тижнями з exit=1 усередині). → окремий `health.json` воркера + сторож, що не залежить від
    LLM; воркер працює у власному дереві на `origin/main`, не в людській робочій теці.
52. **Періодичні «прокидання» довгих сесій кожні 20–30 хв зʼїли ~25 % тижневого ліміту нулем
    роботи** (кожне прокидання — повне перечитування історії повз кеш). → подієва петля:
    прокидатися лише коли є подія; для черги — короткий тік, що при порожній черзі коштує
    копійки.
