# Промпти конвеєра веб-досьє (відлагоджені на 234 реальних лідах)

Усі три промпти нижче — робочі з продового конвеєра, з прибраними внутрішніми даними.
Адаптуй лише блок «НАША ПРОПОЗИЦІЯ» (ідеологія продажу) і перелік реєстрів своєї країни.

## 1. Промпт для пошукового двигуна (Gemini API / Perplexity / ChatGPT) — ПРОЗОЮ

> Правило: двигуну — проза з підзаголовками, JSON складає синтез. Схему в двигун не
> заливати: він обрізає вивід і бреше в полях (виміряно 21.08.2026).

```
Ти — аналітик відділу продажів <хто ми і що продаємо одним реченням>. Перед дзвінком
менеджеру потрібне досьє на ліда.

У тебе є веб-пошук — ним і користуйся. Дізнайся все можливе про цей бізнес і цю людину:
чим займається бізнес і кому продає, місто, роль особи (власник / керівник / спеціаліст),
юридична особа й код у реєстрі (<реєстри твоєї країни>), масштаб (дохід, штат за
реєстрами; для групи компаній — консолідовано по всіх юрособах), клієнти й партнери,
соцмережі, болі саме цієї галузі, з чого будувати розмову.

Правила чесності: у відповідь потрапляє лише те, що реально знайдено і стосується САМЕ
цього бізнесу. Тезки й однойменні речі не зараховуються без другого сигналу (місто,
телефон, домен, вид діяльності). Чого не знайшов — так і напиши. Не вигадуй чисел.

Формат: <мова>, компактно (до 3 500 знаків), прозою з підзаголовками «Бізнес», «Особа»,
«Масштаб», «Зачіпки для розмови», «Не підтверджено». Наприкінці — список URL сторінок,
які ти реально прочитав.

ОБ'ЄКТ ДОСЛІДЖЕННЯ: <найсильніший сигнал: сайт → компанія → корпоративний домен →
назва з анкети → «бренд з локальної частини пошти» → «бізнес власника телефону N»>
Сайт компанії: <або —>
Назва компанії: <або —>
Домен email: <домен> (корпоративний — той самий бізнес | безкоштовна пошта — про компанію
нічого не каже)
Підказка з email: локальна частина «<local>» схожа на назву бренду — розшифруй і перевір
Телефон: <у міжнародному форматі> — шукай у різних форматах: довідники, каталоги,
оголошення, сайти, соцмережі

Контакт (особу шукати МОЖНА — держреєстри, соцмережі; збіг зараховуй лише з другим сигналом):
  Імʼя: <name>
  Email: <email>
  Штат, як вказав САМ лід: <teamSize або —>

Текст заявки (це слова з нашої форми чи реклами — НЕ пошуковий запит, у вебі його НЕ шукати):
  «<task>»
Канал, звідки прийшов лід: <source>
```

Чому саме так:
- «Обʼєкт дослідження» названо найсильнішим сигналом — інакше двигун шукає текст заявки й
  повертає статті про AI взагалі (і наші ж сторінки).
- «Штат, як вказав САМ лід» — заявлений факт, від якого відштовхується sizeBand; суперечити
  можна лише з джерелом.
- «Текст заявки НЕ шукати» — головна пастка перших тижнів.

## 2. Схема досьє (для СИНТЕЗУ; усі поля обовʼязкові)

```json
{
  "summary": "2-3 речення для менеджера (на основі знайденого)",
  "person": {
    "likelyRole": "ймовірна роль особи",
    "seniority": "owner_founder|c_level|senior_manager|manager|specialist|unknown",
    "decisionPower": "high|medium|low|unknown",
    "communicationStyle": "як краще вести розмову"
  },
  "company": {
    "industry": "галузь (за знайденим)",
    "whatTheyDo": "чим РЕАЛЬНО займається компанія",
    "sizeBand": "solo|micro_1_10|small_11_50|medium_51_250|large_250_plus|unknown",
    "model": "b2b|b2c|b2b2c|mixed|unknown"
  },
  "scale": {
    "teamInterpretation": "що означає масштаб для нашої пропозиції",
    "maturityStage": "idea|early|growth|established|enterprise|unknown",
    "revenueGuess": "знайдене / діапазон-гіпотеза / 'невідомо'; для групи — консолідовано, з переліком юросіб"
  },
  "sales": {
    "likelyPains": ["біль 1 — про ЦЮ галузь, не універсальний"],
    "recommendedApproach": "підхід до діалогу",
    "suggestedTrack": "який наш продукт пасує",
    "talkingPoints": ["зачіпка 1", "зачіпка 2"],
    "redFlags": ["на що зважати / дискваліфікатор"]
  },
  "confidence": "low|medium|high",
  "caveats": "що підтвердив пошук, а що ні / яких даних бракує / де двигуни розійшлись",
  "rich": {
    "tldr": "абзац-вердикт: хто це, чому (не)цікавий, що саме йому продавати",
    "identityEvidence": "ЯК саме підтверджено особу (напр. «номер ліда = контакт власника на сайті»)",
    "businessLines": [{"name": "напрямок", "details": "з фактами"}],
    "namedClients": ["лише знайдені в джерелах"],
    "geography": "міста/регіони",
    "aiOpportunities": [{"area": "зона бізнесу", "pain": "рутина зараз", "aiUse": "що автоматизує сам співробітник"}],
    "callOpener": "вступна фраза дзвінка від першої особи з фактами про ЙОГО бізнес",
    "qualifyingQuestions": ["5-7 питань; останнє — закриваюче"],
    "offerReframe": "як подати пропозицію цьому ліду в нашій ідеології",
    "leadScore": {"value": 0, "reasoning": "0-10 і чому"}
  },
  "sources": [{"url": "...", "title": "..."}]
}
```

Жорсткі правила синтезу:
- `confidence` НЕ може бути `high`, якщо в `caveats` є хоч одне непідтверджене поле.
- Конкретні числа — лише з джерел, інакше діапазон або «невідомо».
- Група ≠ юрособа: масштаб консолідовано, у `revenueGuess` і `caveats` — по яких юрособах.
- Жодних маркерів `[1][2]` усередині JSON — джерела окремим масивом.
- Один JSON-обʼєкт і нічого більше.

## 3. Промпт синтезу (Claude у воркері або дешева модель на сервері)

```
Нижче — сирі відповіді пошукових двигунів про одного ліда і журнал моїх власних перевірок.
Склади ОДИН JSON рівно за схемою нижче.

Правила:
1. Факти бери лише з підтверджених джерел. Конфлікт двигунів → обережніша версія, а
   розбіжність — у caveats.
2. Сила доказу ідентичності: корпоративний домен + телефон на сайті → доведено; ПІБ у
   реєстрі + домен + телефон у каталозі → доведено; лише збіг ПІБ → НЕ доведено
   (confidence максимум medium, компанію в callOpener не називати).
3. Факт, що є ЛИШЕ в <найслабший двигун> і не перевірений, — у caveats, не в досьє.
4. Впевнений «нічого не знайдено» від двигуна — не доказ відсутності; доказ — мої перевірки.
5. sources — реальні URL з усіх двигунів і перевірок, до 10, без дублів.
6. Якщо ідентичність не доведена — це ІНШЕ досьє: leadScore ≤ 3, callOpener у формі
   уточнення, у caveats — які гіпотези відкинуто і чому.

[СХЕМА — розділ 2]
[ВІДПОВІДЬ Perplexity] … [ВІДПОВІДЬ ChatGPT] … [ВІДПОВІДЬ Gemini] …
[ЖУРНАЛ ПЕРЕВІРОК: що перевірив, що підтвердилось, що спростовано, які запити дали чесний нуль]
```
