# Архітектура конвеєра веб-досьє на лідів

Референс — продовий конвеєр AI Advisory Board (Next.js + Prisma + Postgres, крони через
crontab, браузерний воркер — планова сесія Claude Desktop з розширенням Claude in Chrome).
Стек — деталь; переносяться **контракти, порядок кроків і сторожі**.

## 1. Схема

```
Лід (форма / реклама / календар)
   │  створення → статус збагачення = pending
   ▼
[A] Миттєва гіпотеза без вебу (дешева модель, секунди)
   │  лід з пошуковим сигналом → позначка «справжнє досьє в дорозі»
   ▼
[B] ЧЕРГА веб-дослідження (SQL-вибірка, без таблиці)
   │
   ├─► [C1] Gemini API + google_search (крон на сервері, щогодини)
   │        → EngineAnswer(engine=gemini, via=api, text, sources[], queries[], usage)
   │
   └─► [C2] Браузерний воркер (щогодини; ЛИШЕ якщо є підписки і залогінений Chrome)
            GET черга → items[]: {leadId, name, prompt, engineAnswers.gemini}
            Perplexity (URL /search?q=…) → сира відповідь
            ChatGPT (вставка по 300 знаків + кнопка) → сира відповідь
            ВЛАСНІ перевірки (curl / службова вкладка) → журнал перевірок
            СИНТЕЗ → JSON за схемою
            POST імпорт {leadId, content, model, engineAnswers[]}
   ▼
[D] Сервер: сторож якорів → парсер JSON → нормалізація → Dossier (JSON у ліді)
    + EngineAnswer по кожному двигуну + журнал перевірок → скоринг → алерт «гарячий»
```

Без [C2] (нема підписок / машини з Chrome) конвеєр повноцінний на [A]+[C1]+власних
перевірках у [C1]-крон-скрипті: синтез тоді робить дешева модель на сервері.

## 2. Контракт даних

**Lead** (те, що є в CRM): `id, name, email, phone, company, website, teamSize, task,
source, stage, createdAt`.

**Dossier** (одна JSON-колонка на ліді, `leadEnrichmentData`):
```json
{
  "summary": "...", "person": {...}, "company": {...}, "scale": {...}, "sales": {...},
  "confidence": "low|medium|high", "caveats": "...", "rich": {...},
  "sources": [{"url": "...", "title": "..."}],
  "meta": {"model": "perplexity-browser/pro-search+chatgpt+gemini-api",
           "generatedAt": "ISO", "inputsUsed": ["website","phone"], "webPending": false},
  "rawAnswers": [{"at": "ISO", "model": "...", "sourcesCount": 7, "text": "≤30 000 знаків"}]
}
```
Схема полів — у `prompts.md`. `rawAnswers` — останні 5 сирих текстів синтезу; це кеш для
картки, а не архів.

**EngineAnswer** (рядкова таблиця; у нас — `LeadActivity` з `type="web_research_raw"`):
```
leadId, type, content ("Сира відповідь ChatGPT: 7 джерел, 4 812 знаків" — для стрічки),
metadata: {engine: perplexity|chatgpt|gemini|claude-verification,
           text (≤30 000), sources[] (≤10 URL), model, runAt, chars,
           // лише для API: via="gemini-api", queries[], usage{prompt,output,thoughts,total}, sourceTitles{}}
createdAt
```
Чому окрема таблиця, а не в JSON ліда: колонку ліда читає кожне відкриття картки і скоринг;
три-чотири повні відповіді на прогін зробили б її архівом, дорогим на читання. Рядкова
таблиця росте вшир безкоштовно для картки. Схему CRM при цьому не міняли — колонки
`type/content/metadata` вже були.

**Черга** (`fetchWebResearchQueue`):
```sql
живий лід AND stage NOT IN (WON, LOST, JUNK, CONVERTED)
AND (пріоритет «дзвінок призначено» OR (досьє без sources AND meta.model NOT LIKE 'browser-prefix%'))
ORDER BY пріоритет, createdAt DESC
```
плюс JS-фільтр `hasResearchableSignal`: компанія / сайт / корпоративний домен пошти /
телефон / локальна частина пошти схожа на бренд / назва бізнесу з тексту заявки.
⚠️ `NOT IN` на nullable-колонці мовчки викидає NULL — стадія має бути NOT NULL або
`OR stage IS NULL`.

**API воркера:** `GET /api/worker/enrich-web?limit=3` (auth заголовком, не query-string) →
`{items:[{leadId,name,createdAt,prompt,engineAnswers:{gemini?}}]}`; `POST` те саме з
`{leadId, content, model?, sources?, engineAnswers?[]}` → `{ok, sourcesCount,
engineAnswersSaved, qualification}`; 422 `dossier_wrong_company` — не імпортувати силоміць.

## 3. Двигуни

| Двигун | Як | Ціна | Що дає | Чого не дає |
|---|---|---|---|---|
| Gemini API + `google_search` (`gemini-3.6-flash`, `thinkingLevel: low`) | `scripts/gemini-grounded.sh` або серверний крон | ≈2,5K токенів ≈ $0,005; grounding — 5 000 безкоштовних запитів/міс, далі $14/1 000 (09.2026) | детермінований пошук, справжні URL після резолву редіректів, ~20 с | глибину ChatGPT; впевненість = перевірити |
| Perplexity Pro у браузері | URL `https://www.perplexity.ai/search?q=<промпт>` | підписка | зачіпки, реєстрові підказки | довгий вивід — обриває ЗАВЖДИ |
| ChatGPT Plus у браузері | клік у поле → `execCommand('insertText')` по 300 знаків → кнопка | підписка | найдовші і найкритичніші відповіді | вигадує «найсильніший доказ» |
| Власні перевірки | curl, DNS, пошук у вкладці | ходи | єдині факти, здобуті самостійно | масштаб |

Perplexity **API** відкинуто через якість (sonar-* помітно гірші за браузерний Pro Search) —
перевірено на реальних лідах. Якщо у твоєму проєкті немає браузерних підписок — конвеєр
живе на Gemini API + власних перевірках.

## 4. Власні перевірки, що дали більше за двигуни (Україна/ЄС; для своєї країни — аналоги)

- Домен: `curl -sI -L http://домен` (404 = сайту нема), `nslookup -type=mx`, `-type=txt`
  (SPF), whois по 43 порту → провайдер пошти = міст до юрособи.
- Локальна частина пошти як окреме слово в `ua-region.com.ua/search?q=` — закривала ліда
  за 20–40 с тричі поспіль; те саме — нік у соцмережах і на біржах фрилансу.
- Телефон **у форматі `+380XXXXXXXXX` суцільно і з дефісами** в Google; голий `0XX…` дає спам.
- Реєстри без логіна через curl: clarity-project (витяг ЄДР, контакти замасковані),
  opendatabot (дохід на працівника — найкорисніший рядок), or.justice.cz, Companies House,
  реєстр VAT Мінфіну Польщі, Prozorro API (POST, матчить нечітко), НАЗК (колишні назви).
- Пошук у вкладці: Google same-origin `fetch('/search?q=')` — ~25 запитів без деградації;
  Bing/DDG вичерпуються і віддають сміття після 10–12.
- Каталоги ніш: barb.ua для бʼюті (телефон замаскований до префікса — греп по префіксу),
  work.ua картка роботодавця (діапазон штату), graintrade (контрагенти поіменно), YouTube
  «про канал» (телефон одним curl).

## 5. Синтез

- Проза від двигунів → JSON за схемою складає синтез (Claude у воркері або дешева модель на
  сервері). Ніколи не проси двигун повернути JSON.
- Конфлікт двигунів → обережніша версія + розбіжність у `caveats`.
- Сила підтвердження: корпоративний домен + телефон на сайті → доведено; ПІБ у реєстрі +
  домен + телефон у каталозі → доведено; лише збіг ПІБ → НЕ доведено, `confidence ≤ medium`,
  компанію в `callOpener` не називати.
- Факт ЛИШЕ з Gemini і не перевірений → у гіпотези/caveats, не в досьє.
- «Ідентифіковано» і «не ідентифіковано» — різні досьє, а не різні `confidence`.
- Порожнє досьє: `confidence: low`, `leadScore 0`, порожні болі, у caveats — що перевірив і
  які гіпотези відкинув. **Імпортувати обовʼязково**, інакше лід повертається в чергу щогодини.

## 6. Сторожі (без них конвеєр «працює» місяцями без роботи)

1. Якорі: домен сайту / назва компанії / поштовий домен ліда МАЄ зустрічатися в тексті
   досьє, інакше 422. Лід без якорів проходить (fail-open), інакше ріжеш лідів без сайту.
2. Черга стоїть > 24 год → алерт «ПК вимкнений / Chrome розлогінений / воркер мертвий».
3. Усі ключі API — 429 → алерт із дедупом 12 год.
4. Добова стеля викликів API (у нас 40) — у безкоштовній зоні при потоці 2–5 лідів/день.
5. Замок на крон (system lock з TTL), щоб два тіки не працювали над одним лідом.
6. Реєстр кронів + маніфест crontab + health-check «коли запускався востаннє».
7. Браузерний воркер прибирає за собою: кожна відкрита вкладка — у журнал того ж ходу,
   закриття з журналу ПЕРЕД підсумком і при зірваному прогоні теж, у зворотному порядку
   створення; «вкладки: закрито N/N» — обовʼязковий рядок підсумку.
8. Для планових воркерів: планувальник показує «успіх» за запуск процесу, а не за роботу —
   тримай окремий `health.json` воркера і сторож, що не залежить від LLM.

## 7. Ціна (виміряно 09.09.2026 на нашому потоці 13–30 лідів/тиждень)

| Стаття | На одне досьє | Примітка |
|---|---|---|
| Браузерний воркер (Claude Desktop, Opus/Fable) | 116–240 викликів інструментів; 23–36 млн токенів читання (переважно кеш) + 80–190K виводу; ≈$70–130 в еквіваленті API | базовий контекст сесії ~135K × кожен хід — ось де обсяг, не в скріншотах |
| Gemini API | ≈2,5K токенів + 1 grounded-запит ≈ $0,005 | thinkingLevel low; без нього роздуми зʼїдають вивід |
| Порожній прогін воркера | ~1–3K токенів після винесення плейбука в окремий файл | до 05.09 — ~280K на кожну порожню перевірку черги |

## 8. Покращення (ранжовано за виграшем / ризиком)

1. **Синтез і власні перевірки — на сервері дешевою моделлю**, браузерні двигуни — лише як
   постачальники сирого тексту. Виграш: 90 % витрати воркера (його ходи — це перевірки й
   синтез, не двигуни). Ризик: якість перевірок дешевої моделі — міряти на 20 лідах поруч.
2. **Двигуни ПАРАЛЕЛЬНО, воркер не чекає жодного окремо** — уже правило; наступний крок —
   винести браузерний збір у детермінований скрипт (Playwright під логіном власника підписок на
   окремому профілі), а Claude лишити лише синтез: 240 ходів → ~10.
3. **Стеля на лід у коді, не в промпті**: 25 хв / 80 викликів — зараз припис у промпті, тобто
   тримається на слухняності моделі; лічильник у запускачі — механічний замок.
4. **Дедуп досліджень по домену/ЄДРПОУ**: другий лід із тієї ж компанії має отримати досьє
   з бази, а не новий прогін (у нас чотири ліди з одного домену стояли в черзі одночасно).
5. **Оцінка якості пост-фактум**: після дзвінка менеджер ставить «досьє допомогло / не
   про того / нічого нового» → метрика на двигун; без неї вага двигунів у синтезі — думка.
6. **Гейт «сміттєвий лід» до черги**: обсценний текст / телефон з однакових цифр / нік
   месенджера замість компанії → одразу junk-досьє без двигунів.
7. **Другий ключ Gemini з кредитами** і budget cap у Google Cloud — зараз один робочий
   ключ із трьох, ліміту витрат не виставлено.
8. **Індексувати EngineAnswer у векторну базу** (ембедінги локальною моделлю) — саме для
   тих майбутніх досліджень, заради яких усе зберігається.

## 9. Рішення за замовчуванням (для ТЗ у новому проєкті)

- Черга = SQL-вибірка; сирі відповіді = рядкова таблиця; досьє = JSON-колонка ліда.
- Перший двигун = Gemini API з google_search (є в кожного за 5 хв: ключ з AI Studio).
- Синтез = дешева модель на сервері (NIM/Ollama/будь-яка з JSON-режимом), промпт з `prompts.md`.
- Крон щогодини, ≤3 ліди за тік, стеля 40/добу, замок на тік, алерт на 429 і на «черга стоїть».
- Браузерні Perplexity/ChatGPT — опційна надбудова, лише за наявності підписок і машини з Chrome.
