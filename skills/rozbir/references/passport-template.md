# Шаблон паспорта — заповнює Claude

Скопіюй структуру нижче в `rozbir/TASK_PASSPORT.md` після першої розповіді.
Замінюй маркери; відсутні відомості — «невідомо», а не вигадані заповнювачі.
Зберігай відповіді й причини суттєвих змін при оновленні, не починай документ заново.
Метадані — на початку файлу, у YAML. `stop_after: spec` зберігай у кожній ревізії.
У `task_type` заміни `A_OR_B` на `A` або `B` за явною відповіддю користувача.
`schema: rozbir.passport.v1` — версія формату, не ревізія змісту; підтримуваний
імпортерами формат — саме `rozbir.passport.v1`. `task_id` — UUID, згенерований
Claude один раз при створенні паспорта; зберігай його при відновленні й усіх ревізіях,
для нової задачі генеруй новий. Старий паспорт без цих полів доповни сам без нової анкети,
записавши міграцію в історію; невідому схему не оголошуй сумісною без звірки полів.

Статуси (чернетка починається з `ПОТРІБНІ_ДАНІ`):
- `ГОТОВО`: є реальний випадок/докази проблеми, межа, критерій «стало краще», облік матеріалів,
  повний Deep Research, 2 приклади для простої задачі або 3–5 різних сценаріїв для складної,
  перевірені підстави рекомендації та облік дефіциту джерел за browser-reference,
  три підходи з оцінкою ефекту або планом вимірювань та явне рішення користувача. Суттєвих прогалин
  для чернетки ТЗ немає; це не підтвердження попиту чи готовності програмувати.
- `ГОТОВО_З_УМОВАМИ`: рамка й рішення користувача є, повний основний звіт збережений, але
  бракує перевірки ключового джерела, достатніх доказових сценаріїв, досвіду покупців
  чи іншої важливої гіпотези. Умову названо в рекомендації та користувач явно погодив
  напрям із цією умовою; не видавай такий прохід за повністю перевірений.
- `ПОТРІБНІ_ДАНІ`: розбір триває або немає реального випадку, повного звіту,
  рішення користувача, зрозумілого напряму чи критичного матеріалу для нього.
  Запиши блокер і одну дію продовження; етап 2 ще не пропонуй.

Для типу Б без власного випадку допускається явно позначений сценарій-гіпотеза,
але не статус `ГОТОВО` без реальних доказів проблеми/досвіду покупців.
Погоджене додаткове дослідження не замінюй планом: поки воно триває, розбір триває.
Якщо користувач явно відклав/скасував його й обрав напрям з умовою, запиши це;
критичний для безпечного вибору блокер залишає `ПОТРІБНІ_ДАНІ`.
Непрочитаний несуттєвий файл не блокує завершення, але лишається в інвентарі.

Позначай джерело біля кожного важливого факту: `[зі слів роль/автор, дата]`,
`[з документа materialy/файл, сторінка/аркуш/діапазон]`,
`[з дослідження research-0N.md, URL; перевірено/не перевірено]`,
`[з симуляції interviews-sim.md, персона]`, `[припущення]`.
Погодження рішення не змінює статус його неперевірених підстав.
Симуляція не є підтвердженим досвідом, не підвищує статус готовності й не замінює докази.

## Службовий реєстр відповідей

Веде Claude, людина нічого не заповнює; не показуй реєстр у читанці чи питаннях.
Один рядок на смислову відповідь, сталий ID не залежить від формулювання питання.
Обов'язкові ID — у таблиці нижче; для інших відповідей додавай короткі `domain.meaning`.
Статус рівно один: `підтверджено` (явна відповідь людини), `з документа` (прочитане
з точним місцем), `припущення` (включно з симуляцією), `невідомо`, `суперечність`.
Біля значення — автор/дата або файл/місце/URL і перевірка; «з документа» не означає
незалежної перевірки факту. Суперечність містить обидві версії, не стирає одну з них.
При оновленні збережи ID, актуальне значення/статус і причину заміни в історії;
синхронізуй зі змістом паспорта, не створюй паралельний журнал відповідей.
Імпортер зіставляє питання за ID та змістом: перші два статуси використовує без
повторного питання, припущення переносить із позначкою; невідоме/суперечність
уточнює лише коли це суттєва прогалина для ТЗ. Згода з напрямом не підтверджує всі рядки.
