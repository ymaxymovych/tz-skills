# Deep Research через зовнішній Chrome

Інструкції для Claude; користувачу показуй лише поточну дію з готових текстів.
Адаптовано механіку browser-llm: перевірка вводу/режиму, окрема вкладка,
повний текст із URL, зупинка на вході/CAPTCHA. Працюй у доступному акаунті
користувача; не створюй новий і не змінюй тариф.

## Дозволений канал і одна спроба підключення

Лише розширення **Claude in Chrome** у зовнішньому Google Chrome користувача,
де він уже залогінений. Виявляй інструменти за можливістю інтеграції, а не за
наявністю довільного browser-tool. Типові дії: контекст вкладок, створення вкладки,
навігація, пошук елемента, введення у форму, читання повного тексту.
Виклик читання контексту/дозволеної вкладки має реально спрацювати;
сам список інструментів не доводить підключення. Не показуй приватний список вкладок.

**Заборонено:** вбудований браузер Claude / Claude_Browser, headless, Playwright,
API Perplexity та WebSearch як заміна Deep Research або для обходу ручної перевірки.
Не використовуй інший браузер, анонімну сесію чи запит у URL як обхід помилки вводу.

Якщо інтеграції немає, покажи ОДНУ підказку:

```text
У Claude Code введіть /chrome і виконайте підказку підключення розширення Claude in Chrome. Успіх — панель показує «Status: Enabled» і «Extension: Installed». Після цього напишіть «готово»; я перевірю з'єднання. Інструкція: https://code.claude.com/docs/en/chrome
```

Після відповіді перевір один раз читання вкладки. Якщо `/chrome` недоступна в
цьому інтерфейсі або читання не працює — не води користувача колами налаштувань.
Скажи: «З'єднання не запрацювало. Дослідження проведемо у вашому Chrome вручну;
я даватиму по одній дії». Продовжуй розповідь; ручний маршрут — коли запит готовий.
Офіційна довідка: [Claude Code + Chrome](https://code.claude.com/docs/en/chrome).
Не обіцяй сумісність кожного інтерфейсу чи тарифу.

## Підготувати й показати запит

Візьми підтверджений переказ і матеріали. Знеособ 150–500 слів контексту, включно
з рідкісними деталями, за якими можна впізнати компанію. Дай 3–5 конкретних
дослідницьких питань, включно з обов'язковими блоками нижче. Увесь остаточний запит покажи користувачу в блоці коду на кроці 2
до відправлення; відповідь «далі» дозволяє перейти з цим текстом до дослідження.
Виправлений запит знову покажи. Не надсилай приватні документи/скріншоти.
Приклад каркаса, який заповнюєш сам:

```text
Проведи Deep Research про способи вирішення цієї робочої задачі.
Контекст: [знеособлений останній випадок, проблема, межа, обов'язкові обмеження].
Початкове бачення як гіпотеза: [ідея, яку можна спростувати].
1. Покажи [2 для простої задачі / 3–5 різних сценаріїв для складної]
   конкретних прикладів схожого процесу: як надходить робота →
   що робить людина → що робить система → де обмеження. Дай первинні URL.
2. Порівняй: спростити процес / наявні інструменти; купити платний сервіс;
   взяти open source й доробити; зробити з нуля лише якщо перші три не підходять.
   Що залишиться ручним, хто підтримує рішення, які витрати підтверджені?
3. Окремий блок «Готові рішення»: хто вже вирішував схожі задачі й як;
   open source (репозиторій, ліцензія й комерційне використання, активність,
   мова та TypeScript/JavaScript, покриття/прогалини, розгортання);
   платні конкуренти (для кого, тариф/ціна з датою/URL або ціну не публікують,
   українська/Україна, слабкі місця); відгуки про обидва типи рішень — похвала,
   скарги й причини відмови з URL/датами, реклама окремо від досвіду людей.
   [Розгорни всі вимоги ready-solutions.md у цьому запиті перед показом.]
   Окремий блок «Що люди реально кажуть»: біль, наслідки й обхідні способи
   самої проблеми — форуми, Reddit, публічні спільноти, коментарі; URL й дати.
4. Що може спростувати початкову ідею, яких відомостей бракує для вибору?
Використовуй публічні джерела; шукай українською й англійською.
Орієнтир покриття — 5–8 відкритих релевантних джерел, з них ≥ 2 первинних;
за меншої кількості надійних джерел назви дефіцит, не додавай слабких заради числа.
Звіт українською, простими словами, головний висновок на початку.
Посилання й дати біля тверджень. Відділяй первинні факти, рекламу,
досвід окремих людей і свої висновки. Не вигадуй цифр, цитат або попиту.
Якщо джерело недоступне чи прикладу немає — чесно познач прогалину.
```

Для продукту на продаж додай питання з [product-track.md](product-track.md):
попит, ніші та минулі дії покупців. Спільні для А і Б «Готові рішення» — за
[ready-solutions.md](ready-solutions.md), прочитай і включи його вимоги в запит.
Не проси «довести вільну нішу». Для внутрішнього процесу не додавай аналіз ринку.

## Глибина й журнал досліджень

До показу запиту Claude сам обирає кількість сценаріїв: для простого однорідного
процесу — 2; для складної задачі з різними ролями, потоками чи суттєвими винятками —
3–5. Потрібні різні способи роботи, а не кілька описів одного інструмента.
Це орієнтир за наявності надійних джерел; нестачу й вплив на рекомендацію збережи.
У `evidence.md` зафіксуй фактично відкриті релевантні джерела, які з них первинні,
і перевірку 2–3 вирішальних тверджень: твердження → URL → що підтверджено/спростовано
або лишилось неперевіреним. Самі посилання AI-звіту не рахуй як відкриті джерела.
Покриття оцінюй для всієї задачі, без дублювання URL заради кількості.
У читанці лиши короткий висновок; сценарії й прогалини — у наявних `details`.
У HTML повторюй блок `.example` з окремими заголовком, потоком, джерелом і перевіркою
до потрібної кількості; недоказові порожні приклади прибери, дефіцит назви текстом.

За замовчуванням — один основний запит з ОБОМА обов'язковими блоками:
«Готові рішення» й «Що люди реально кажуть». Якщо не влазить, підготуй другий
запит як частину основного пакета; покажи обидва тексти на кроці 2. Після «далі»
виконай пакет без окремого питання «чи хочете». Якщо потреба розділити виникла
пізніше, покажи новий текст для перевірки знеособлення й дочекайся «далі»;
обов'язковість дослідження не скасовує перевірки зовнішнього тексту.
Для великої/ризикової задачі або важливих прогалин понад ці блоки
запропонуй ще 1–2 прицільні запити.
Дай для кожного мету, повний знеособлений текст, користь для рішення й оцінку часу;
невідомі квоти/витрати познач невідомими. Одна наступна дія — обрати весь пакет,
частину або відмовитися. Лише після явного вибору запускай погоджені запити.
Кожен відправлений текст має бути показаний; після правок покажи його знову.
Дозвіл на показаний пакет охоплює його тексти, але не нові/змінені. Не вигадуй потребу в додатковому
пакеті для невеликої задачі, де основне дослідження вже дає достатні підстави.

Прицільний запит вирішує одну конкретну прогалину: наприклад, сумісність готових
інструментів із процесом або ризик помилок у документах. Не повторює весь перший звіт.
Окремий запит «Що люди реально кажуть» охоплює відгуки, форуми, Reddit,
публічні Facebook-групи, YouTube-коментарі та пошукові запити. Питання:
де болить сама проблема, які наслідки й обхідні способи, що вже пробували.
Досвід з конкретними рішеннями зберігай у «Готових рішеннях», не змішуй блоки.
Потрібні прямі URL і дати, роль/контекст автора, повторювані теми та контрприклади.
Недоступну платформу познач; не обходь закриті групи, не вигадуй коментарів,
цитат або частотності запитів. Окремий допис — сигнал, не доведений масштаб попиту.

У кожного запиту власний `research-0N.md`; далі в маршрутах «поточний файл» —
саме він, не завжди `research-01.md`. Збережи перед запуском:

```markdown
# Дослідження [ID]: [мета]
Журнал: [заплановано / виконано / відкрито]
Рішення користувача: [очікується / погоджено: точні слова й дата / відкладено / відхилено]
Стан виконання: [підготовлено / запущено / часткове / завершено / недоступне]
Дата/час, сервіс, режим, канал: [розширення / ручний імпорт]
Тред і місце продовження: [URL, поточна дія або «ще немає»]
Прогалина й вплив на вибір: […]
## Повний знеособлений запит
[…]
## Оригінальний звіт із URL
[Не заповнюй переказом; до отримання — «ще немає».]
## Перевірки й відкриті питання
[Твердження → первинне джерело → результат перевірки → наступна дія.]
```

Стислий запис кожного дослідження дублюй у загальному журналі `evidence.md`.
«Виконано» означає збережений повний звіт, а не лише клік запуску; невирішені
питання звіту залиш у колонці відкритого. За блокера/відмови — «відкрито» з причиною.
Той самий дозволений маршрут і перевірка першоджерел діють для кожного дослідження.
Інший сервіс дозволений для іншого погодженого питання, а не дубля вже запущеного.

## Автоматичний маршрут через розширення

1. Створи власну вкладку, не змінюй відкриті вкладки користувача. Відкрий один сервіс:
   https://gemini.google.com/app або https://www.perplexity.ai/ . Обери той, де
   доступний режим; другий — запасний, якщо перший не дозволяє запуск.
2. Прочитай стан сторінки: вхід, поле запиту, Research/Deep Research та обмеження.
   Наявність безкоштовного акаунта не гарантує квоту; платний тариф теж не доказ.
   На login/CAPTCHA попроси людину пройти лише цей екран, пароль не запитуй.
3. Знайди поле за доступним ref/DOM, введи запит у форму. Для довгого тексту
   використовуй form-input, не довгу імітацію друку. Повторно прочитай значення:
   текст має бути повним. Обери Research у Perplexity або Deep Research у Gemini
   ДО запуску. Якщо поле не приймає текст — одна повторна перевірка, потім ручний шлях.
4. До натискання запуску створи/онови поточний `rozbir/research-0N.md`:
   запит, дата/час, сервіс, режим, канал «розширення» або «ручний імпорт», стан
   «підготовлено», місце продовження. Після відправлення — «запущено», приватний
   URL треду й видиме підтвердження запуску. Невідомий результат кліку спершу
   перевір у тому самому треді; не відправляй повторно.
5. Gemini може спершу показати план: підтвердь запуск дослідження, якщо потрібен
   окремий клік. План не є звітом. Поки сервіс працює, оновлюй власні файли;
   перевіряй стан приблизно раз на хвилину, без частого перечитування всього тексту.
   Через приблизно 30 хв без готового звіту збережи стан і одну дію повернення.
6. Дочекайся завершеного стану та відкрий повний звіт («Open report» або фактична
   кнопка). Зчитай увесь текст разом із реальними URL джерел; довге — частинами
   без пропусків. Збережи оригінальний звіт під метаданими, без переказу замість нього.
   Якщо текст обірваний — стан «часткове», доповнюй із того ж треду.
7. Через те саме розширення відкрий першоджерела 2–3 вирішальних тверджень.
   Додатково перевір репозиторії open source, ліцензії, ціни й вирішальні відгуки
   за ready-solutions.md у тому самому Chrome; цей перелік не обмежений 2–3 URL.
   Перевір зміст, контекст, дату й обмеження; успішне відкриття URL не є доказом.
   Результат перевірки занеси в evidence.md. Недоступне познач «не перевірено».
8. Не публікуй тред і не створюй share-посилання. Після збереження повного тексту,
   URL та перевірок закрий лише свої тимчасові вкладки; чужих не чіпай.

## Ручний маршрут — показувати суворо по ОДНІЙ дії

Не показуй користувачу весь список. Наступну дію давай після відповіді/результату
попередньої. Gemini — перша пропозиція, якщо користувач не назвав інший доступний сервіс.
У паспорті й поточному research-0N.md зберігай ручну дію для відновлення.

1. «Відкрийте у вашому Chrome https://gemini.google.com/app і напишіть “відкрито”».
   Якщо потрібен вхід — наступна єдина дія: увійти самостійно.
2. «Вставте цей готовий запит у поле повідомлення; поки не надсилайте».
   Покажи повний знеособлений запит у блоці коду; попроси написати «вставлено».
3. «Біля поля повідомлення відкрийте меню інструментів і оберіть Deep Research;
   напишіть “обрано”». Назву/місце звіряй з доступним описом екрана; якщо кнопки
   немає, попроси назвати видимі пункти, не вигадуй координат. У Perplexity — Research.
4. «Натисніть кнопку надсилання запиту й напишіть, що з'явилося».
   Якщо Gemini показав план — окремою наступною дією попроси натиснути кнопку
   початку дослідження з цього плану. Не називай показаний план результатом.
5. «Дочекайтеся готового звіту з висновками й джерелами, а не лише плану.
   Коли він готовий, напишіть “звіт готовий”». Якщо є «Open report» — наступною
   дією попроси відкрити звіт.
6. ЄДИНИЙ спосіб перенесення: «Виділіть увесь звіт (Ctrl+A на сторінці звіту),
   скопіюйте й вставте сюди в чат — я збережу його з посиланнями».
   Збережи вставлене в поточний research-0N.md як ручний імпорт. Перевір наявність
   висновків, закінчення й URL. План, короткий переказ чи обрізаний текст — не повний звіт.
   Якщо джерела не перенеслися — одна дія: скопіювати їх із розділу джерел того ж звіту.
7. Для вирішального твердження, яке без розширення не перевірити: дай ОДИН точний
   URL першоджерела зі звіту й попроси відкрити його в Chrome. Наступною дією —
   скопіювати в чат релевантний текст із контекстом. Збережи потрібний доказ у
   evidence.md як ручний імпорт; оцінюй зміст. Повтори для іншого ключового джерела
   лише за потреби. Якщо це неможливо, лиши «не перевірено» й умовний висновок.

Якщо режим недоступний/ліміт вичерпано ДО запуску — запропонуй відкрити другий
сервіс (одна дія). У ньому той самий маршрут із Research або Deep Research.
Якщо запит уже запущений, не переходь до другого сервісу для дублювання.
Якщо обидва недоступні, збережи запит, стан і місце продовження та скажи:

```text
Глибоке дослідження зараз недоступне в обох сервісах, тому цей крок ще не завершено. Запит і все зроблене збережені; нічого купувати не потрібно. Коли доступ з'явиться, відкрийте ту саму папку й запустіть /rozbir — продовжимо звідси.
```

Не підмінюй відсутній звіт звичайним пошуком. Повторний `/rozbir` читає збережений
стан: завершене не запускається знову; надіслане перевіряється у тому самому треді;
для підготовленого запиту продовжується конкретна незавершена дія.
