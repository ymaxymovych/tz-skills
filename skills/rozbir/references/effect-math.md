# Ефект у цифрах

Читай на кроці 4 для обох типів задач. Рахуй у спільному періоді та валюті;
період і одиниці вказуй біля результату. За замовчуванням зручно порівнювати тиждень.

## Вхідні дані та походження

Таблиця: величина → значення й одиниця → джерело/період вибірки → статус.
Статуси: **виміряно** (журнал, хронометраж, документ), **оцінено зі слів**
(хто й коли), **припущення** (чому так, діапазон) або **невідомо**.
Не перетворюй «приблизно година» на виміряні 60 хвилин.

- `N` — кількість випадків на тиждень; `t0` — сумарні активні людино-хвилини
  на випадок. Якщо `m` людей справді працюють по `t` хв, `t0 = t × m`.
  Якщо час уже сумарний для команди, на `m` вдруге НЕ множ.
- `r` — повна вартість людино-години, якщо відома; за різних ролей рахуй
  їхні години й ставки окремо. Без ставки показуй години, гроші — формулою.
- `E0` — кількість помилок за тиждень; `c` — середня додаткова вартість помилки.
  Якщо дано ймовірність `p0`, то `E0 = N × p0`.
- `O0` — поточні регулярні платежі за інструменти/послуги за тиждень,
  якщо входять у межі порівняння; нуль лише за відомої відсутності таких витрат.
- `t_i`, `E_i`, `h_i` — для кожного підходу: залишковий час на випадок,
  помилки за тиждень, підтримка в людино-годинах за тиждень;
  `O_i` — регулярні платежі за тиждень; `K_i` — одноразові витрати впровадження.
  Прогноз без перевірки завжди припущення, краще діапазоном.

## Формули для кожного з чотирьох підходів

Порівнюй: 1) спростити процес / наявні інструменти; 2) купити платний сервіс;
3) взяти open source й доробити; 4) зробити своє з нуля. Для четвертого поясни,
чому 1–3 не підходять; якщо він нежиттєздатний, назви це, не вигадуй кошторис.
Ціни сервісів — із тарифом, URL та датою перевірки з блоку «Готові рішення».
Для open source окремо оціни доробку, розгортання, хостинг, оновлення й підтримку;
відкрита ліцензія не робить ці витрати нульовими. Вартість робіт — діапазон
із припущеннями про години й ставку або «невідомо», а не нібито ринкова ціна.

```text
H0 = N × t0 / 60                            поточні людино-години/тиждень
L0 = H0 × r + E0 × c + O0                   поточні витрати/тиждень
H_i = N × t_i / 60 + h_i                    години після зміни з підтримкою
L_i = H_i × r + E_i × c + O_i               витрати після зміни/тиждень
ΔH_i = H0 − H_i                             вивільнені години/тиждень
ΔL_i = L0 − L_i                             очікуваний ефект/тиждень
Окупність_i = K_i / ΔL_i                    тижні, лише якщо ΔL_i > 0
```

Нульовий/від'ємний ефект покажи чесно; за невідомих `K_i` окупність невідома.
Якщо частина витрат невідома, покажи відому частину й формулу повної, не називай
частковий підсумок усіма витратами.
Для місяця явно обери перерахунок, наприклад `52/12` тижня, не змішуй з «4 тижні».
Не називай весь поточний час усувною втратою. Відділяй активну роботу від очікування;
скорочення очікування не множ на погодинну ставку без обґрунтування.
Не враховуй час виправлення помилки двічі у `t0` і `c`; поясни склад вартості помилки.
Вивільнений час — місткість команди, не гарантована економія фонду оплати праці.
До одноразових витрат включай налаштування й освоєння, якщо їх можна оцінити.

Для типу Б ці формули рахують ефект для покупця/його процесу. Окрему економіку
продажу рахуй лише за наявності даних: внесок із продажу = ціна − змінні витрати;
результат за період = кількість продажів × внесок − постійні витрати.
Кількість продажів без реальних даних — сценарій, не доведений попит.

## Якщо чисел мало

Використай відоме, для решти покажи формулу або діапазон із явними припущеннями.
Не роби вигляд, що нуль означає відсутню вартість, і не блокуй розбір довгою анкетою.
Назви 2–3 наступні числа з найбільшою цінністю для вибору, наприклад:
кількість випадків за типовий тиждень; активні людино-хвилини на випадок для всієї
команди; кількість і додаткова вартість помилок за той самий період.
Якщо важливіша ставка чи вартість готового інструмента — заміни ними менш важливий пункт.
Запропонуй короткий спосіб виміряти й відповідальну роль, не вимагай великого аудиту.

## Час до першого корисного результату

Для кожного з чотирьох підходів задай конкретний перший корисний результат для цієї
задачі й умовний діапазон календарного часу від початку впровадження до нього
(дні/тижні), а не до завершення всієї розробки чи окупності. Порівнюй однакову користь.
Поруч назви припущення: доступність відповідальної людини, готовність даних,
доступи, інтеграції та погодження. Наприклад: «1–3 тижні, припущення: дані готові,
відповідальний доступний 5 год/тиждень, одна інтеграція без очікування доступу».
Це приклад формату, не типовий строк. Не обіцяй дедлайн; коли навіть умовний
діапазон не має підстав, пиши «невідомо» й назви залежність, яку треба перевірити.
Збережи оцінки в паспорті й у згорнутій таблиці читанки, без додаткової анкети.

У читанці нагорі — оцінка ефекту й надійність цифр або «для оцінки бракує […]».
У згорнутих деталях — входи з походженням, підстановка у формули, чотири підходи,
витрати впровадження й підтримки, діапазон та найбільш чутливе припущення.
